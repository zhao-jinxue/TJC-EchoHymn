## 任务 1：按节翻页歌词 + 手动/自动 + 曲谱+歌词模式（实现）

### 提问

歌词按「一节一页」分页显示（正歌+副歌为一页），提供上一页/下一页/页码导航与「手动/自动」切换（自动按音频时长等分推进）；新增「曲谱」显示模式，简谱谱行与歌词逐列对齐、副歌谱每页重复、任何字号下不换行。

### 解决思路

- 分页语义：`LyricPage` = 一节正歌 + 副歌（如有）；页数 = 正歌节数，副歌不增页。
- 自动翻页：播放器时长优先，为 0/不可用时回退 DB `audio_durations`；进度→页索引换算并钳位末页。
- 曲谱对齐：**不在运行时重做歌词-音符对齐**，直接采用库内第 1 节已存的 `hymn_score_char.note_index` 列位模板，各节歌词按字序落列（一谱多词天然对齐）。
- 不换行硬约束：字号上限 = 可用宽 ÷ 页内最宽谱行（全角 2 / 半角 1 度量）。
- 持久化：`lyricAutoMode` 走 `AppState`/`AppStateService` 既有串行写队列。

### 最终结果

- **完成结论**：全部实现完成；`test/lyric_page_score_test.dart` 39/39 通过；`flutter analyze` 无告警；Windows release 构建成功。
- **关键改动**：`models/hymn.dart`（chorus/audio_durations 解析）、`models/hymn_score.dart`（新增，谱模型+code_seq 还原）、`widgets/hymn_display.dart`（分页/导航/手动自动/模式切换）、`widgets/score_lyric_view.dart`（新增，曲谱歌词渲染）、`services/sqlite_repository.dart`（谱表检查/loadScorePages/码位缓存/副歌谱探测）、`services/app_state_service.dart` + `screens/home_screen.dart`（lyricAutoMode 持久化接线）。
- **验证方式**：单元测试 39 用例 + release 构建 + 实机截图点击验证（见任务 2）。
- **遗留问题**：无（功能层面）。

## 任务 2：实机验证（Win32 合成点击 + 截图比对）

### 提问

在 release 真机上验证：手动翻页（含首页/末页禁用）、手动/自动切换的可见变化与重启持久化。

### 解决思路

- 用 PowerShell + Win32 `SetCursorPos/mouse_event` 合成点击，`CopyFromScreen` 截图，Python/PIL 像素扫描定位控件、图像差分判定点击是否生效。
- 关键坑：截图（.NET VirtualScreen）与 `SetCursorPos`（pwsh 为 DPI-unaware，DC 报 96DPI/2048 宽）处于**同一逻辑坐标空间，1:1 直用**；早期按 1.2 比例换算导致点击偏移误判「未生效」。
- 判定点击生效最可靠的通道是**应用日志**（`logs/` 的 `[ACTION]` 条目），优于像素差分。

### 最终结果

- **完成结论**：手动翻页全链路实机验证通过；手动/自动切换与持久化经 `state.json` + 日志证实生效。
- **验证细节**：
  - 翻页：343 首 3 页，「下一页」推进至「第 3 / 3 节」时 `>` 置灰禁用、`<` 可回退——正确。
  - 模式按钮：日志确认 lyrics/scoreLyric/numbered/staff 四种切换均响应。
  - 手动/自动：`state.json` 落盘 `lyricAutoMode: false`（默认 true），证明切换生效且持久化写通道正常。
  - 音频自然播完自动下一首（343→339）联动正常。
- **遇到的困难**：① 截图坐标空间误判（以为需 ÷1.2 换算），实际 1:1；② 小按钮点击坐标需像素扫描取真实边界（按钮行 y≈159–188），凭视觉估算多次落空；③ 用户同时在手动操作应用，合成点击与真实操作交织，最终以应用日志为准裁定。
- **遗留问题**：重启后 `lyricAutoMode` UI 恢复的目检未单独做（落盘已证实，恢复逻辑有单测覆盖）；验证期截图工具链已按一次性产物清理，未入库。
