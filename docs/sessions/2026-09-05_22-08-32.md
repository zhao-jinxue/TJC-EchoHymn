# 简谱/五线谱图片宽度驱动缩放

- 日期：2026-09-05
- 工具链：Cline + DeepSeek API
- 涉及模块：显示区（hymn_display 谱面图片查看器）

## 任务 1：谱面图片放大宽度受限于初始宽度，两侧空白无法利用

### 提问

简谱和五线谱是加载图片显示的，滚轮可放大；但初始化时宽度被限制，放大时明明左右两侧还有空白区域，却无法查看放大的图片。要求：放大后的最大宽度 = 歌词区当前显示宽度，初始显示宽度为最小宽度；放大过程中宽度变大、高度变高，超出部分通过滚动条向下查看。

### 解决思路

- 根因：`_buildScore` 用 `InteractiveViewer`（默认 `maxScale=2.5`）包 Image。简谱/五线谱是纵向长图，初始按高度 contain 后宽度只占歌词区一小条；滚轮放大到 2.5× 后宽度仍到不了两侧空白边缘，再放就撞 `maxScale` 硬上限，且 InteractiveViewer 无纵向滚动条语义（滚轮=缩放、拖拽=平移），与用户预期不符。
- 候选方案：
  - A. 给 InteractiveViewer 算动态 `maxScale = 视口宽/初始显示宽`——能解决"放大上限"，但缩放中心随拖拽漂移、无滚动条、上下留白行为不可控；
  - B. **宽度驱动的自定义查看器**（选定）——Image 显式尺寸 = 初始宽 × zoom（zoom∈[1, 视口宽/初始宽]），高度按图片宽高比同步放大，外层 `Scrollbar + SingleChildScrollView` 提供纵向滚动条。语义与用户描述逐条对应，行为确定。
- 关键实现点：
  - `ImageStreamListener` 解码得到图片自然尺寸（ImageProvider.resolve），据初始 contain 规则算最小宽度 baseW（横向图 baseW=视口宽 → 缩放区间退化 [1,1]，只剩纵向滚动，符合"宽度不超过歌词区"）；
  - `Listener.onPointerSignal` 捕滚轮，指数因子放大/缩小，钳制 [1, maxZoom]；
  - 视口宽由 `LayoutBuilder` 实时取——窗口拉伸/最大化/字号等级变化自动跟随；
  - 换歌/换谱面（didUpdateWidget path 变化）缩放复位为 1；
  - 纵向超出时 `Scrollbar(thumbVisibility: true)` 常显。

### 最终结果

- **完成结论**：谱面缩放改为宽度驱动（初始宽 → 歌词区宽），两侧空白可被放大利用，超出高度用滚动条下翻；analyze 0 issues，Release 构建通过。
- **关键改动**：
  - `hymn_app/lib/widgets/hymn_display.dart`：`_buildScore` 弃用 `InteractiveViewer`，新增 `_ScoreImageView`（滚轮按指数因子调 zoom∈[1, 歌词区宽/初始宽]；`ImageStreamListener` 解码取图片自然尺寸；`LayoutBuilder` 实时取视口宽；`Scrollbar(thumbVisibility)+SingleChildScrollView` 纵向滚动；path 变化复位）
  - `hymn_app/lib/widgets/user_manual_dialog.dart`：「显示模式」小节谱面描述同步新交互
- **验证方式**：`flutter analyze`（0 issues）+ `flutter build windows --release`（成功）
- **遇到的困难**：① 本机 Flutter 版本 `ImageStream` 无公开 `dispose`，改为仅 `removeListener`；② `NetworkImage`/`FileImage` 条件表达式被分析器求 LUB 为 `Object`，改 if/else 分支赋值规避；③ `PointerScrollEvent` 需显式 `import flutter/gestures.dart`。
- **遗留问题**：待用户实机走查——滚轮放大到两侧无空白、放大后滚动条下翻、横向图只剩纵向滚动、切歌复位、窗口最大化/字号等级变化后上限跟随、换肤下滚动条观感。

## 任务 2：出现滚动条后滚轮"滚动+缩放"双响应冲突

### 提问

滚轮可以放大图片，但界面出现滚动条后想向下查看，滚轮滚动时滚动条动了、图片也同步缩小。求解决方案。

### 解决思路

- 根因：`Listener.onPointerSignal` 是"旁观式"监听不拦截事件，`SingleChildScrollView`（Scrollable）对同一滚轮事件各自响应——缩放与滚动同时发生。
- 语义拆分（选定）：无滚动条时内容无滚动空间，普通滚轮=缩放（零冲突）；出现滚动条后普通滚轮=滚动，**Ctrl+滚轮=缩放**（与浏览器缩放惯例一致）。
- 双响应防治：Flutter 滚轮经 `PointerSignalResolver` **先注册者赢**（`GestureBinding.instance.pointerSignalResolver`，SDK binding.dart L354/L534，Scrollable 于 scrollable.dart L962 注册）。命中测试路径**深者优先**，故认领用的 Listener 必须放在滚动内容**内部**（放外层会输给 Scrollable 内部监听器）；缩放时以空回调先注册占住 resolver，Scrollable 的注册即被忽略。

### 最终结果

- **完成结论**：滚轮语义按场景分流，Ctrl+滚轮缩放不再触发滚动；analyze 0 issues + Release 构建通过。
- **关键改动**：
  - `hymn_app/lib/widgets/hymn_display.dart`：`_ScoreImageView` 滚轮 Listener 移入滚动内容内部，新增 `_onWheel`（`HardwareKeyboard.isControlPressed` 分流 + `PointerSignalResolver.register` 认领）；补 `flutter/services.dart` 导入
  - `hymn_app/lib/widgets/user_manual_dialog.dart`：谱面操作说明同步"滚轮滚动 / Ctrl+滚轮缩放"
- **验证方式**：`flutter analyze`（0 issues）+ `flutter build windows --release`（成功）
- **遇到的困难**：外层 Listener 无认领权（注册输给 Scrollable）→ Listener 移入内容层；`HardwareKeyboard` 不在 material 导出内需 `show` 导入。
- **遗留问题**：待实机验证——放大后普通滚轮纯滚动、Ctrl+滚轮只缩放不跳动、缩回一屏后滚轮恢复缩放语义。

## 任务 5：滚轮语义简化——放弃状态切换，固定两条规则

### 提问

"未出现滚动条时滚轮缩放 / 出现滚动条后滚轮滚动、Ctrl+滚轮缩放"三种情况不是最优解，直接简化为两种：**Ctrl+滚轮=谱面缩放，滚轮=谱面上下滚动**。

### 解决思路

- 固定语义优于状态切换：用户无需感知"有没有滚动条"这一内部状态，任何时刻 Ctrl+滚轮都缩放、普通滚轮都滚动，可预期性最强。
- 代码上反而更简单：`_onWheel` 删除 `canScrollV` 分流参数，非 Ctrl 直接 return（不足一屏时 Scrollable 无滚动空间，滚轮自然不动，无需特判）；Ctrl 分支认领 resolver 的逻辑保持无条件执行（认领在无滚动空间时无副作用）。
- Listener 必须留在滚动内容内部的结论不变（Ctrl+滚轮时仍需先于 Scrollable 注册）。

### 最终结果

- **完成结论**：滚轮语义固定为两条规则；手册「显示模式」子项（4→3 条）与快捷键表（谱面 3 行并 2 行）同步；analyze 0 issues + Release 构建通过。
- **关键改动**：
  - `hymn_app/lib/widgets/hymn_display.dart`：`_onWheel` 简化（去 canScrollV 参数）、类文档注释更新
  - `hymn_app/lib/widgets/user_manual_dialog.dart`：显示模式子项、kShortcutList 同步
- **验证方式**：`flutter analyze` + `flutter build windows --release`
- **遇到的困难**：无
- **遗留问题**：待实机验证——初始视图（无滚动条）下普通滚轮不动、Ctrl+滚轮可直接放大；放大后普通滚轮纯滚动、Ctrl+滚轮缩放不跳滚动位置。
