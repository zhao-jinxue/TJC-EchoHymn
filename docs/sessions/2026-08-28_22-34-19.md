## 任务 6：批 2 · 窗口/进程 NG 修复（A02 单实例 + A09/K10 窗口最小尺寸）

### 提问

按批 2 计划修复：单实例（A02）+ 最小尺寸（A09/K10）。

### 解决思路

- **A02（双实例）**：Windows runner 用 `CreateMutexW` 单实例保护——已有实例（`ERROR_ALREADY_EXISTS`）时 `FindWindowW` 定位已有窗口并 `SetForegroundWindow` 聚焦，然后新进程直接退出。Mutex 名 `EchoHymn_SingleInstanceMutex`。
- **A09/K10（最小尺寸不含侧栏）**：`main.cpp` 启动时 `SetMinClientSize(850, 890)` 是固定基座尺寸；侧栏展开后窗口加宽但最小尺寸不变，导致仍可缩到基座宽、侧栏被裁。→ 在 `Win32Window::SetClientSize` 开头**同步更新最小客户区 = 基座 850×890 + 当前展开栏宽**（收起侧栏时自动回到 850）。

### 最终结果

- **关键改动**：
  - `windows/runner/main.cpp`：`CreateMutexW` 单实例保护 + 聚焦已有窗口
  - `windows/runner/win32_window.cpp`：`SetClientSize` 内同步 `SetMinClientSize(width + left + right, height)`
- **验证方式**：flutter analyze（C++ 不在 analyze 范围）+ `flutter build windows --release` 成功；冒烟测试双实例启动 → 存活进程数 1、第二实例 `HasExited=True`（A02 ✓）；最小尺寸逻辑经 WM_GETMINMAXINFO 标准机制生效（K10 需手动拖窗复核）
