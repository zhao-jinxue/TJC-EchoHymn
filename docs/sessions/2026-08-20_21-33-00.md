### 第二轮反馈修正（DPI 物理像素 + 抽屉式侧栏）

用户反馈（两张新截图）：

1. 启动后实机尺寸 1045×1104、最小 833×691——**不是**理想的 850×890（原因：用户屏幕 DPI≈125%，逻辑 850×890 被缩成物理 1045×1104）
2. **展开侧栏 = 窗口整体变宽**（非挤压歌词区）：左栏物理 350px、右栏物理 600px；展开后 1200 / 1450 / 1800px

### 修正方案（物理像素驱动）

- **窗口客户区改为物理像素**：`main.cpp` `SetClientSize(850,890)` + `SetMinClientSize(850,890)`（`win32_window.cpp` 用 `AdjustWindowRectEx` 换算外框，保证客户区精确 850×890 物理像素，与 DPI 无关）
- **MethodChannel**（`echo_hymn/window`）：`flutter_window.cpp` 注册 `setClientSize`；Dart 侧 `home_screen.dart` 展开/收起侧栏时调用——窗口整体变宽（850+350+600，全展开 1800）
- **侧栏宽度 DPI 换算**：左栏 350/dpr、右栏 600/dpr 逻辑像素（保证各 DPI 下物理宽度恒为 350/600）
- 头文件补充 `method_channel.h`/`standard_method_codec.h` include（首次构建报 C2039，已修复）

### 第五轮 bug 修复（歌词区被侧栏挤压）

用户反馈：展开左栏后界面异常（`ScreenShot_2026-08-20_224300_291.png`），怀疑缩放比例问题。

### 排查

1. 千问视觉解析截图：注意到「左侧列表约占 30%、歌词区约占 70%」——**歌词区被挤压变窄**了
2. 根因：`_buildBody` 中歌词区用的是 `Expanded`（弹性填充），侧栏展开后窗口加宽 350，但歌词区是 Expanded 会被拉伸/挤压，**并非固定基座 850 宽**

### 修复（`home_screen.dart`）

- 歌词区改为 **`SizedBox(width: baseWidth)`**（850/dpr 逻辑宽），不再 Expanded
- 整体内容用 **`Center + SizedBox(totalWidth)`** 包裹：总宽 = 基座 850 + 展开侧栏宽，固定宽度居中
  - 侧栏展开后基座歌词区**保持 850 物理宽不变**，不会被挤压/拉伸
- 顶栏/底栏 40px 高度不变

### 第六轮反馈（窗口等比缩放）

用户反馈：启动时各区域大小合适，但最大化和右下角缩放时**内容没有等比放大**；左右栏展开后也没等比缩放——不合理。

### 修复（FittedBox 等比缩放）

`home_screen.dart` `build` 改为：

- 外层 `LayoutBuilder + Center + FittedBox(fit: BoxFit.contain)`
- 内层固定逻辑尺寸 = 基座 850×890 + 已展开侧栏宽（/dpr）
- **窗口客户区任意变化时整棵树（顶栏+主体+底栏）等比缩放**，不再固定不变
- `_buildBody` 移除多余 Center/SizedBox，简化为 Row（子项宽度各自固定）

### 第七轮反馈（等比缩放仍未生效 + 用户强烈不满）

用户反馈：最大化后 UI 变大了，但**内层所有内容没有变化**——FittedBox 方案实际未生效，浪费了用户时间与 token。（向用户致歉）

### 根因复盘

- FittedBox 给 child 传**未约束/unbounded 约束**，子树内 Column + Expanded 的组合在无高度约束下布局不可靠
- 且外层 Center 松约束下 FittedBox 的适配行为与预期不符——**视觉上没有产生缩放**

### 修复（Transform 渲染矩阵缩放，不依赖布局约束）

`home_screen.dart` build 改为 **`Align(center) + Transform.scale`**：

- Transform.scale 在**渲染层**乘变换矩阵，直接对绘制内容进行等比缩放——不需要子布局有特殊约束，必定反应在画面上
- scale = min(窗口宽/内容宽, 窗口高/内容高)（contain，不裁切不变形）
- Align 撑满窗口，SizedBox(680×712) 在窗口中心，缩放后内容从中心放大
