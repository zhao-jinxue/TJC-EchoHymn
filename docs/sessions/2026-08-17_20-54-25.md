## 任务 1：解决 git push 到 GitHub 的 SSH 认证失败

### 提问

用户反馈 `git push -u origin main` 报错：

```
git@github.com: Permission denied (publickey).
fatal: Could not read from remote repository.
```

并附带 known_hosts 中路径显示乱码 `/c/Users/\320\241.../.ssh` 的信息，询问"怎么解决问题"。

### 解决思路

1. 现象定位：Git Bash 自带的 ssh 无法处理中文用户名路径 `C:\Users\小蔡爱金雪`，被转义成乱码，导致 ssh 找不到 `~/.ssh/id_ed25519` 密钥 → 认证失败。
2. 方案对比：
   - 给 Git Bash 设置 `HOME` 环境变量 → 需改全局配置，影响面大
   - 改用 Windows 自带 OpenSSH（支持中文路径）→ 零配置、立即生效，选定此方案
3. 细节陷阱：`git config core.sshCommand` 中路径**必须使用正斜杠**（`C:/Windows/...`），反斜杠会被 git 当作转义符吃掉（实测报 `C:WindowsSystem32...` 错误）；密钥路径无需 `-i` 参数，Windows OpenSSH 自动查找默认位置。

### 最终结果

- **完成结论**：SSH 认证修复成功，`Hi zhao-jinxue! You've successfully authenticated`。
- **关键改动**：执行 `git config core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe -o StrictHostKeyChecking=accept-new"`
- **验证方式**：`ssh -T git@github.com` 确认身份；随后 push 进入传输阶段。
- **遇到的困难**：中文用户名导致的两处坑——Git Bash 路径转义乱码、PowerShell 传参丢中文（均通过改用 Windows OpenSSH + 正斜杠路径规避）。
- **遗留问题**：无。

## 任务 2：push 因仓库过大（2.76GB）中断

### 提问

SSH 修复后 push 报 `client_loop: send disconnect: Connection reset`，在 17% 处中断。仓库 3.3GB 数据被 git 跟踪。

### 解决思路

1. 分析：`data/Hymn_Downloads/`（音频/谱图/PDF，3.3GB）被 git 跟踪，远超 GitHub 1GB 硬上限。
2. 方案：因远程仓库为空、无协作风险 → 用 `git filter-branch --index-filter "git rm -r --cached --ignore-unmatch data/Hymn_Downloads"` 从全部 39 个历史提交移除大文件，保留 `data/tjc_hymn.db`。
3. 清理：删除 `refs/original/` 残留引用 + `git reflog expire --expire=now --all` + `git gc --prune=now --aggressive`。

### 最终结果

- **完成结论**：仓库从 2.76 GiB 缩小至 15.10 MiB，push 成功（502 个对象、15.09 MiB）。
- **关键改动**：全部提交的 tree 移除 Hymn_Downloads；`.gitignore` 同步更新。
- **验证方式**：`git count-objects -vH`（size-pack 15.10 MiB）；`git rev-list --objects --all` 无 Hymn_Downloads 残留；`git push -u origin main` 成功。
- **遇到的困难**：第一次 `git gc` 未生效——`refs/original/` 下 3 个旧标签引用持有旧大文件对象，导致无法清除；删除 `refs/original` 后重新 gc 才成功。
- **遗留问题**：无。

## 任务 4（重大事故）：filter-branch 重写误删工作区原始数据

### 提问

用户严厉指出："你上一次操作，竟然把重要的原始数据 data\Hymn_Downloads 删除了，你可以设置git不跟踪，但不能删除原始文件，只是重大失误，你要自我检讨，并记录在全局规则中，现有 data\Hymn_Downloads 的目录和文件是我手动恢复的"。

### 解决思路（检讨）

1. 事故根因：`git filter-branch --index-filter "git rm -r --cached"` 的 `--cached` 只控制"历史中是否保留"，但 **filter-branch 重写完成后会强制 checkout 工作区到新 HEAD**，被移除的文件从磁盘物理删除。我未预见到这一副作用，也未在重写前备份工作区。
2. 正确做法应是在重写历史**之前**将 `data\Hymn_Downloads` 完整备份到仓库外（如 `e:\backup\`），重写验证后再恢复。
3. 教训固化：写入全局 `.clinerules`「git 历史重写安全守则」（6 条铁律：重写前必须备份并校验 / 删除 ≠ 忽略 / 数据类操作默认只读等），确保所有会话不再重蹈覆辙。

### 最终结果

- **完成结论**：用户已手动恢复全部数据；全局规则已记录事故与铁律；数据完整性经核实完好。
- **关键改动**：
  - 全局规则 `C:\Users\小蔡爱金雪\.clinerules` 新增「git 历史重写安全守则」
  - 数据核验：474 目录 / 464 mp3 / 792 m4a / 948 pdf / 948 png / 474 checksums.json / url_map.txt 均完好
- **验证方式**：`Get-ChildItem` 文件计数核验；`git status` 干净。
- **遇到的困难**：无法恢复已被覆盖的 git 对象（备份标签 filter-branch 时也被重写），只能依靠手动恢复。
- **遗留问题**：无（教训已入规则防再犯）。

## 任务 6：Markdown 文档格式检查报错（MD033 / MD024）

### 提问

用户反馈 `docs/sessions/_template.md` 和 `docs/sessions/2026-08-17_20-54-25.md` 有 VS Code 的文档格式检查报错，询问原因与如何避免。

### 解决思路

两类报错均来自 **markdownlint**（VS Code 常用 Markdown 检查扩展）默认规则：

1. **`_template.md`（MD033 no-inline-html）**：模板中大量使用尖括号占位符（如 `<会话主题>`、`<YYYY-MM-DD>`、`<一句话总结...>`），Markdown 将其解析为内联 HTML 标签 → 触发 MD033。
2. **会话日志（MD024 no-duplicate-heading）**：5 个任务段落里 `### 提问` / `### 解决思路` / `### 最终结果` 各重复 5 次，markdownlint 默认对全文件查重 → 触发 MD024。

方案对比：

- 改写占位符语法（去尖括号）→ 模板可读性变差，且不能根治会话日志的重复标题
- 项目级配置 markdownlint 规则按需关闭/放宽 → 一劳永逸，选定此方案

### 最终结果

- **完成结论**：配置 markdownlint 规则消除两类报错：MD033 关闭（允许模板尖括号占位符）、MD024 改为 `siblings_only`（仅同章节内重复才报错，跨任务重复标题豁免）。
- **关键改动**：
  1. 首次方案 `.vscode/settings.json` 的 `markdownlint.config` 块 → 被新版扩展标记为**弃用**（"This property is deprecated. Please use a configuration file like .markdownlint.json/.markdownlint.yaml instead."）
  2. 最终方案：新建 **`.markdownlint.json`** 独立配置文件承载规则；从 `.vscode/settings.json` 移除弃用属性，仅保留 git/cmake 配置
- **验证方式**：配置保存后需重新加载 VS Code 窗口生效；打开两个文件确认无报错。
- **遇到的困难**：markdownlint 新版扩展弃用了 settings.json 内联配置方式，需迁移到独立 `.markdownlint.json`；随后又发现 `.clinerules` 与会话日志仍有告警——`MD013`（行过长，中文长行超 80 字符）与 `MD040`（代码块未指定语言，终端报错粘贴块），在 `.markdownlint.json` 中一并关闭这两条。
- **遗留问题**：若未来新增其他 markdownlint 规则冲突，可在 `.markdownlint.json` 中继续追加豁免。
