## 任务 1：Android 版 UI 与后台功能移植规划

### 提问

用户：需要开发对应的 Android 版本的 UI 与后台功能；怎么知道跑的是 Android 系统而不是 Windows 界面？是否有模拟器或虚拟机？追问：环境装到 D 盘；先把计划写入文档，再执行阶段 0。

### 解决思路

- 实测盘点：Flutter 3.44.8 已启用 android；`hymn_app/android/` 是 create 默认工程；无 Android SDK/JDK/设备；Hypervisor 已开（模拟器可 WHPX 加速）；dl.google.com 可达；D 盘 106GB 空闲。
- 平台判定三层解释：运行时（APK 跑在 Android 系统内）、代码层（`Platform.isAndroid` / `AppPaths.isMobile` / 条件导入）、构建层（`flutter run -d` 选 target）。
- 载体选型：用户确认走**官方 Android 模拟器**（Android Studio + AVD），无需手机。
- 移植识别出的 Windows 强绑定点：自绘标题栏+`echo_hymn/window` 通道、850×890 基座+Transform.scale、全局快捷键、exe 同级 state.json/素材目录、中文路径音频。
- 计划分四阶段（环境→最小可跑→数据链路→UI 移动化），全文落档 `docs/ANDROID_PLAN.md`。

### 最终结果

- **完成结论**：计划文档落档；阶段 0 环境搭建进行中（SDK 组件后台下载安装）
- **关键改动**：新增 `docs/ANDROID_PLAN.md`（现状盘点/D 盘目录规划/阶段 0~3/风险清单）；新增本日志
- **验证方式**：`docs/ANDROID_PLAN.md` 存在；阶段 0 验证以 `flutter doctor` + `flutter devices` 为准
- **遇到的困难**（阶段 0 实况记录）：
  1. winget 后台安装报 "No package found"（`Google.AndroidStudio` 实际存在），前台正常，疑似后台会话未继承 winget 源 → 放弃后台安装
  2. 官方直链 `android-studio-2026.1.4.7-windows.exe` 返回 404；下载到的 1.26GB 包运行无文件落地（非 NSIS 静默，改走纯命令行路线，不再依赖 Studio 本体）
  3. 安装顺序坑：并行执行时下载未完成即解压失败 → 改串行执行
  4. 最终改用 **cmdline-tools + JDK 17**（均 D 盘）：`D:\Android\cmdline-tools\latest`（sdkmanager 12.0 验证通过）+ `D:\Java\jdk-17.0.20.1+1`（openjdk 17 LTS 验证通过）
  5. 已设 User 级环境变量：`JAVA_HOME` / `ANDROID_HOME=D:\Android\Sdk` / `ANDROID_AVD_HOME=D:\Android\avd` / PATH 追加 cmdline-tools、platform-tools、emulator
  6. 许可全部接受（`sdkmanager --licenses` 40 个 y → All SDK package licenses accepted）
- **遗留问题**：Gradle/Maven 国内镜像待配置；素材大包分发方案待对齐；keystore 签名后置；Android Studio GUI 本体未装（模拟器不依赖它；如后续需要 GUI 调试可装 C 盘默认版）

## 任务 2：执行阶段 0——Android 环境搭建（D 盘）

### 提问

用户："装到 D 盘。先将这计划写入文档，再执行阶段 0 的任务。"

### 解决思路

载体定为官方模拟器后，最小依赖链 = JDK 17 + cmdline-tools + SDK 组件 + AVD；Android Studio GUI 并非硬依赖（AVD/模拟器全有命令行通道）。执行中因 Studio 安装器不可静默改目录，果断切换纯命令行路线，保证全落 D 盘。

### 最终结果

- **完成结论**：阶段 0 全部达成——`flutter doctor` Android toolchain 全绿（SDK 36.0.0）；`echohymn_avd`（Pixel 7 / API 34 x86_64）冷启动成功，`flutter devices` 列出 `emulator-5554 • android-x64 • Android 14`
- **关键改动**：`docs/ANDROID_PLAN.md`（计划 + 执行实况 + 踩坑记录）；本日志；系统侧：`D:\Android\Sdk`（≈5.9GB，platform-tools 37.0.1 / platforms 34+36 / build-tools 34+36 / emulator 37.1.11 / 系统镜像 34 google_apis x86_64）、`D:\Android\avd`、`D:\Java\jdk-17.0.20.1+1`、User 级 JAVA_HOME/ANDROID_HOME/ANDROID_AVD_HOME/PATH、`flutter config --android-sdk`；任务 1 结果中"cmdline-tools 在 D:\Android\cmdline-tools"后续已归位到 `D:\Android\Sdk\cmdline-tools\latest`（Flutter 规范布局）
- **验证方式**：`sdkmanager --list_installed`（5 组件齐）→ `adb devices`（device 态）→ `getprop sys.boot_completed=1` → `flutter doctor` / `flutter devices` / `flutter emulators` 三连通过
- **遇到的困难**：① winget 经 Start-Process 脱离控制台报 "No package found"（前台正常）→ 安装类操作一律前台；② Studio 新安装器（CrossInstall）静默参数失效、1.26GB 下载白费（包已删）→ 放弃 GUI；③ MSI 装 JDK 需 UAC（1603）→ 改 Microsoft OpenJDK ZIP 免安装版；④ cmd `set X=Y&& ` 空格截断致组件错装到 D:\Android 根 → Move-Item 归位；⑤ Flutter 3.44 要求 compileSdk 36 → 补装 platforms;android-36 + build-tools;36.0.0；⑥ 有依赖的命令被并行执行（解压先于下载完成）→ 改串行
- **遗留问题**：PATH 等 User 环境变量需新开终端生效（本会话内已用绝对路径规避）；阶段 1 首次构建若 Gradle 下载超时按风险清单配国内镜像
