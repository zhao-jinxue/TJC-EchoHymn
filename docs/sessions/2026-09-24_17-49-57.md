## 任务 2：v1.8.0 安装包实机复验 + 「运行中卸载 → 残留文件」修复

### 提问

（用户，接续我给出的候选清单）
1. `v1.8.0 安装包实机全流程复验`；
2. 追加反馈：**「卸载程序的时候，发现一个 bug：程序在运行的时候，执行卸载程序，导致没有强制关闭已运行程序，导致有残留文件存在」**。

### 解决思路

**1) 先取证（不猜）**

- 只读勘察现场：`D:\Program Files\EchoHymn` **仍存在**（创建 16:06:11 / 最后写入 16:53:09），`dir /a` 显示 **0 文件 0 字节**；
  注册表 `…\Uninstall\*_is1` 中**已无 EchoHymn 项**，`Get-Process echo_hymn` 无进程；
  → 事实链：16:06 安装 v1.8.0 → 用户实机试用 → 16:53 卸载（程序在运行）→ 程序文件/目录被占用使删除失败 → 残留；
  而 Inno 已删除 `unins000.exe` 与注册表卸载项 → **用户失去「设置 → 应用」里的卸载入口**，只能手工删目录。

**2) 根因定位（读源码 + 查官方文档）**

| 机制 | 覆盖范围 | 本安装包是否受覆盖 |
| --- | --- | --- |
| `CloseApplications=yes`（Inno 官方）：Setup 非静默时在"准备安装"页用 **Windows Restart Manager** 关闭占用 `[Files]`/`[InstallDelete]` 文件的程序 | 仅 **Setup**，且仅其**自身文件条目** | ❌ 主程序与素材由 `ExtractArchive({tmp}\payload.7z)` / 素材 7z 释放；卸载由 `DelTree({app},…)` 整树删除——都不在 Restart Manager 感知范围 |
| `AppMutex`（Inno 官方）：Setup **与 Uninstall** 启动时检查命名互斥体，命中则提示"请先关闭…然后点确定继续，或取消退出" | 安装 + 卸载 | ⚠️ 可加但**不够**：官方交互允许「确定继续」，用户照样能在程序运行时继续 → 仍残留（故本次**不采用**，改为显式处理） |
| `DelTree(Path, IsDir, DeleteFiles, DeleteSubdirsAlso): Boolean` | 返回 `True` 仅当**全部删除成功** | 现有代码 `DelTree(App, True, True, True);` **丢弃返回值** → 失败无感知、无补救 |

**3) 修复方案（安装/卸载双向、确定性闭环）**

在 `installer/echohymn.iss` 的 `[Code]` 增加运行中实例处理族，并在三个位置接入：

- `EHAppRunning`：**双通道检测** —— `CheckForMutexes('EchoHymn_SingleInstanceMutex')`（与 `hymn_app/windows/runner/main.cpp` 的单实例互斥体同名）+ `FindWindowByWindowName('echo_hymn')` 兜底；
  （托盘隐藏时窗口不可见但**进程与外置互斥体仍在**，两条通道都能命中）
- `EHCloseApp`：`Exec('{sys}\taskkill.exe', '/F /T /IM echo_hymn.exe')` + `Sleep(600)` 后复查；
  为什么用 `/F` 而非平滑关闭：软件可能处于托盘隐藏态，或首次关闭会弹「直接关闭 / 进入系统托盘」询问框——平滑关闭会被这两个分支阻断而无法结束进程；
- `EHEnsureAppClosed(Silent)`：非静默时弹**中文确认框**（「是」=立即结束并继续 / 「否」=中止），静默模式（`/SILENT`、`/VERYSILENT`、静默卸载）免交互直接结束；
- `PrepareToInstall`（升级安装前）：未关闭则返回非空字符串 → **安装中止并显示提示**；
- `InitializeUninstall`（卸载前）：未关闭则 `Result := False` → **干净中止卸载**（不动任何文件、不删注册表项）；
- `CurUninstallStepChanged(usUninstall)`：删除前再探一次（防用户在向导期间又启动），改用 `EHDeleteTree`（**检查返回值 + 最多重试 5 次**，每次先补杀进程），仍失败则用 `EHResidueList` 列出残留路径并弹窗告知手动清理——**绝不静默留下半截目录**；
- 顺带修掉 ISCC 编译提示：`FileCopy` → `CopyFile`（官方改名提示）。

**4) 复验通道（可重复、无人值守）**

- `tools/build_installer.ps1` 新增 **`-IssOnly`**：复用既有 `installer/payload.7z` + `output/EchoHymn_Data_v*.7z`，只重跑 ISCC + 重出双 SHA256（改 `.iss` 秒级迭代；原 `-SkipStaging` 因构建后 `staging/` 即删而实际不可用）；
- 新增 `tools/verify_installer.ps1`：**静默装 → 启动程序 → 程序运行中静默卸载 → 检查程序文件残留**；`-Baseline <修复前安装包>` 可加跑对照阶段（期望 RESIDUE，即复现 bug）。判据说明：静默卸载按设计**保留个人数据**（`data\tjc_hymn.db`/`state.json`/`logs`），故「干净」= 无程序文件残留（`echo_hymn.exe`/`unins000.exe`/`data\app.so`/`flutter_windows.dll`/`flutter_assets`）且无残留进程。

## 会话总结

- 本次共处理 **5 个任务**：① 会话启动/上下文续接；② **v1.8.0 安装包实机复验 + 「运行中卸载 → 残留文件」bug 修复**（含 A/B 对照验证）；③ 两个软著生成器 `ruff`/`pyright` 告警清零 + 产物回归比对；④ 仓库外一次性脚本 `ruanzhu_migrate.py` 固化入库为 `tools/migrate_ruanzhu_docs.py`；⑤ `ruanzhu-workspace/` 迁入 `docs/ruanzhu/workspace/` 并确立"软著材料唯一归档位置"规则。
- 关键收获：
  1. **自解包安装包必须自己管"占用"**：`CloseApplications`/Windows Restart Manager 只覆盖安装程序自身 `[Files]`/`[InstallDelete]`；本工程主程序与素材由 `ExtractArchive` 释放、卸载由 `DelTree` 整树删除，都在其感知之外 → 运行中的实例会让删除**静默失败**，而 Inno 仍会删掉卸载器与注册表项（用户失去再卸入口）。正确做法：**检测（互斥体 + 窗口标题双通道）→ 确认 → `taskkill /F` → 删除后复核（`DelTree` 返回值 + 重试 + 残留清单）**。
  2. **"干净"的判据要贴合设计语义**：静默卸载按设计保留个人数据（`tjc_hymn.db`/`state.json`/`logs`），故判据必须是"**无程序文件残留**"而非"目录消失"；并且 **A/B 对照**（把修复前安装包一起跑）把"我认为修好了"升级为"确定性复现 + 确定性根治"（A：残留 7 个被占用的程序文件、进程仍在；B：进程 0、程序文件 0 残留）。
  3. **验证必须真跑**：本次两次踩坑都靠"跑起来/比一次"抓到——① 编辑器替换把下行 `])` 一并吞掉（语法破坏）；② `replace_version()` 忘了返回替换后的文本（沙盒往返比对当场暴露）。静态检查（ruff/pyright/py_compile）能兜语法与类型，但**行为正确性只能靠端到端跑**。
  4. **同一支线的记录必须只留一处**：软著支线曾同时存在于仓库根 `ruanzhu-workspace/` 与 `docs/ruanzhu/v<版本>/`；本次不只搬家，还把规则写进 **`docs/README.md`（总纲）+ 项目 `.clinerules`（新会话自动注入）+ 根 `README.md`**，从"约定"变成每次会话都会读到的硬约束。
- 遗留事项：
  1. **GUI 通道人工走查**：非静默卸载弹窗的「是（结束进程并继续）/ 否（干净中止）」两条分支，以及"关闭行为=进入系统托盘 + GUI 卸载"组合（脚本只覆盖静默通道）；
  2. 用户机器上历史残留的空目录 `D:\Program Files\EchoHymn` 待确认后删除；
  3. 其他 `tools/*.py` 的既有 ruff/pyright 告警（全量 141 项）未清——建议后续统一处理并加 `ruff.toml` 收口规则集；
  4. 软著说明书仍缺**实机整屏截图 4~6 张**（材料人工环节，清单已列补图方法）；
