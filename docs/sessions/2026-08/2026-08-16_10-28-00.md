## 任务 9：恢复校验机制（不再盲猜）

### 提问

指出恢复过程没有校验：应像翻页恢复一样「执行→校验→确认/重试」，而不是盲猜；例如翻页成功后再滚动、滚动后再校验位置；其他状态（音频版本等）恢复也应有校验逻辑，重启后可快速确定是否正确恢复。

### 解决思路

- 滚动校验：`jumpTo` 后读 `ctrl.offset`，与目标误差 ≤2px 才算成功，否则多帧重试（10 次）；`hasClients` 保护避免 position 异常；target 在列表挂载后计算。
- 锚点统一校验 `_finishRestore`：左栏/音频版本/播放列表位置/滚动逐项比对，异常时底部状态栏红色「恢复待确认：…」报告（提交 `96d89ba`）。
- 反馈修正：恢复成功清空报告（状态栏回归播放信息）、播放时清报告、`hasClients` 防护（提交 `9bc754f`）。

### 最终结果

- **完成结论**：恢复由「盲操作」变为「执行+校验+报告」，异常可被状态栏文字直接暴露。
- **关键改动**：`lib/screens/home_screen.dart`（`_scrollToCurrentHymnRetry` 校验、`_finishRestore`、状态栏报告）。
- **验证方式**：flutter analyze 0 issues + 多次自动发布成功。
- **遇到的困难**：用户连报两轮偏差（报告常驻占状态栏、hasClients 崩溃隐患），逐轮补齐「成功清报告」「播放清报告」「防护」。
- **遗留问题**：校验报告机制在后续锚点重构中进一步演进。

## 任务 12：左栏三栏目基类/子类架构重构

### 提问

询问三个左栏栏目（诗歌列表/默认歌单/个人歌单）是同一套代码还是三套；随后要求用 Dart 基类/子类拆开——共用部分（如点击播放）放基类，独立部分（如滚动条恢复）放各子类，防止代码修改互相影响。

### 解决思路

Dart 面向对象支持 `abstract class`/`extends`/`@override`。设计：

- 基类 `LeftPanel`（StatefulWidget）+ `LeftPanelState`：公共 `hymnTile` 渲染、`playHymn` 播放（含回调和刷新）、`scrollToCurrent` 滚动工具、抽象 `restoreSaved(anchor)`；`anchor` 变化时自动触发恢复（initState/didUpdateWidget 延后一帧）
- 三子类：`HymnListPanel`（搜索+分页+页码恢复）、`DefaultPlaylistsPanel`（分类树+二级展开恢复）、`MyPlaylistsPanel`（歌单管理+展开恢复），各自独立 ScrollController 与交互
- `HomeScreen` 精简为协调者：三 Tab 分发（switch）、anchor 传递、状态保存、播放来源回调

### 最终结果

- **完成结论**：三个栏目彻底拆分为「基类契约 + 子类实现」，共用逻辑在基类、独立逻辑在子类，改动互不影响。
- **关键改动**：新增 `lib/widgets/panels/{left_panel_base, hymn_list_panel, default_playlists_panel, my_playlists_panel}.dart`；重写 `lib/screens/home_screen.dart`（-909 行/+精简）。
- **验证方式**：flutter analyze 0 issues（修复三面板 `anchor` 参数未暴露、导入路径、`_EmptyHint` 缺失等）；自动发布成功（`716fcd4`）。
- **遇到的困难**：面板文件多次写入被编辑器截断/未落盘造成「类不存在」，经 list/search 确认后重建；导入路径 `../../playlist_dialog.dart` 误写更正。
- **遗留问题**：重构后三面板的显示/交互/恢复需在实机逐项验证（记录入 SESSION_SUMMARY 遗留清单）。
