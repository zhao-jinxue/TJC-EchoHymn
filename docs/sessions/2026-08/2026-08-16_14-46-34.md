## 任务 2：默认歌单（默认歌单-思慕天家-434）状态保存/恢复失败

### 提问

三个面板能正常显示、诗歌列表滚动能恢复；但默认歌单选「盼望-思慕天家-434」重启后未恢复，且关闭时 state.json 信息不对（缺 subcategory/playlistName，leftTab 混乱）。

### 解决思路

读 `state.json` 确认 leftTab=hymnList、subcategory/playlistName 为空。排查链：保存方 `HomeScreen._saveState` → 播放回调 `_onPlayback` → 面板 `playHymn` → `PlaybackEvent` 发现**4 个关联根因**：

1. `PlaybackEvent` 缺少来源字段（面板从不告知播放来自哪个二级目录/歌单）
2. `_onPlayback` 无条件清空来源且只用「全量列表」识别歌曲列表
3. `_saveState` 用 `identical(list, _allHymns)` 判断全量恒 false（`getAllHymns()` 每次新建 List）
4. `_init` 恢复时无条件用全量列表做播放上下文

### 最终结果

- **完成结论**：默认歌单/个人歌单的播放来源正确保存与恢复，播放列表按来源构建。
- **关键改动**：
  - `left_panel_base.dart`：`PlaybackEvent` 增加 `sourceSubcategory`/`sourcePlaylistName`
  - `default_playlists_panel.dart` / `my_playlists_panel.dart`：行点击透传来源
  - `home_screen.dart`：`_onPlayback` 按来源记录 + `_saveState` 按来源优先级 + `_init` 按来源构建恢复列表
- **验证方式**：flutter analyze 0 issues、构建成功、实机验证恢复。
- **遇到的困难**：来源语义在重构后的三层回调中传递易遗漏。
- **遗留问题**：无。

## 任务 8：界面全简体 + 搜索简繁双向（OpenCC 排障）

### 提问

1. 三个歌单诗歌名全部繁体转简体显示；2. 搜索框输入简体搜不到繁体诗歌，若转换已完成能否搜到，否则输入标题时转繁体再检索。

### 解决思路

先尝试用 OpenCC FFI 补 `toTraditional`（简→繁 s2t.json）实现双向搜索；随后排查「未转换/搜不到」现象——最终发现本机 opencc.dll 与 Flutter UI 线程不兼容：

- probe 实证：`DynamicLibrary.open` 成功、`opencc_init_converter` 成功（id=1）、但 `convert` 在 UI 线程挂起致白屏；且 Bindings 一次性 lookup 缺 `opencc_delete_converter` 等符号导致崩溃。
- 结论：弃用 OpenCC FFI，改**纯 Dart 逐字查表**。

### 最终结果

- **完成结论**：转换最终以纯 Dart 实现（任务 10 落地），OpenCC FFI 彻底移除。
- **关键改动**（本任务过程性）：`chinese_convert_service.dart`/`native`/`stub` 多次迭代排障、`opencc_probe.dart`（诊断探针，最终删除）。
- **验证方式**：probe v2/v4 日志逐符号验证；程序从崩溃恢复稳定。
- **遇到的困难**：重大——OpenCC 原生库在本机的 UI 线程挂起/符号缺失问题被反复误判为中文路径/VC 运行库，最终靠「最小验证方案」（实际 convert 调用）定位，明确与转换本身无关。
- **遗留问题**：无（交由纯 Dart 方案解决）。

## 任务 9：VC 运行库就近打包

### 提问

### 最终结果

- **完成结论**：发布包含 VC 运行库，不依赖系统是否安装 VC++ Redistributable。
- **关键改动**：`windows/CMakeLists.txt`（install 规则）。
- **验证方式**：构建后 Release 目录与发布目录均含 3 个 VC DLL。
- **遇到的困难**：无。
- **遗留问题**：opencc.dll 随依赖一并存在但已不被调用（纯 Dart 后无影响）。

## 任务 10：纯 Dart 简繁映射方案落地

### 提问

纯 Dart 简繁映射方案怎么实现？除了常用字映射表，还要从 `data/tjc_hymn.db` 的 tjc_hymn 表获取所有繁体文字建立简体映射，用于显示和搜索，用以上方案实现并验证。

### 解决思路

三层实现：① 提取数据库全量字符（3022 个）→ 用 zhconv 逐字转换生成映射（繁→简 1052 / 简→繁 1025）；② `chinese_convert_map.dart` 纯 Dart const Map；③ `chinese_convert_native.dart` 改为逐字查表（接口不变，零原生依赖）；固化生成脚本 `tools/gen_convert_map.py`；移除 `flutter_opencc_ffi` 依赖与 assets/opencc 声明。

### 最终结果

- **完成结论**：纯 Dart 简繁双向转换落地并生效。
- **关键改动**：新增 `lib/data/chinese_convert_map.dart`、`tools/gen_convert_map.py`；重写 `chinese_convert_native.dart`；清理 `pubspec.yaml`（移除 opencc 依赖/assets）。
- **验证方式**：脚本生成映射成功；analyze 0 issues；构建成功；启动稳定（PID=21800）；实机验证标题简体显示、搜索「释放」匹配「蒙主釋放」。
- **遇到的困难**：命令行内联 Python 转义导致语法错误，改脚本文件执行。
- **遗留问题**：一简对多繁取数据库首现，个别字可能不精确（可后续用词组表增强）。
