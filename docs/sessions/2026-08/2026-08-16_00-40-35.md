## 任务 2：根治无声——just_audio「Loading interrupted」→ audioplayers（v1.0.0）

### 提问

用户反馈（检测到应用弹出 Toast）：**「音频加载失败:Loading interrupted」**。

（简短口头要求）继续修复，让音频真正发声。

### 解决思路

- 上一任务 Toast 修复生效——从「无声且无提示」变为能看到具体错误，证明错误链路已通。
- 根因分析：just_audio_windows 的 `AudioSource.uri(Uri.file(abs))` 对**中文/繁体路径**（`Hymn_Downloads/001_1頌讚獨一真神/1_鋼琴版.m4a`）做 URI 百分号编码，插件侧 `MediaSource::CreateFromUri` 解码失败 → 静默中断（`Loading interrupted`）。
- 方案对比：
  - **A. 继续 just_audio**：需规避 URI 编码（如临时改名/ASCII 路径），不治本且目录 474 首全中文路径不可行。
  - **B. audioplayers（选定）**：`DeviceFileSource(path)` **直传平台原生文件路径**，不经 URI 编码；audioplayers_windows 走系统媒体栈（Windows 上即 Media Foundation），m4a/mp3 原生解码，零外部下载。对外接口（statusStream/positionStream/currentHymn/playNext…）全部保持，仅重写 `audio_service.dart` 内部实现。
- 选定方案 B。

### 最终结果

- **完成结论**：audioplayers 6.8.1 替换 just_audio，中文路径音频播放成功，**用户确认声音正常播放**；同日打 tag `v1.0.0` 首版。
- **关键改动**：
  - `hymn_app/pubspec.yaml`：删除 `just_audio`/`just_audio_windows`/`audio_session`，新增 `audioplayers: ^6.1.0`（实际解析 6.8.1）。
  - `hymn_app/lib/services/audio_service.dart`：整体重写为 audioplayers 后端——`AudioPlayer()`；`DeviceFileSource(abs)` / `UrlSource(abs)`；`onPlayerComplete` → `playNext()`（自动连播唯一通道）；`onPlayerStateChanged` 映射 PlayerStatus；togglePlayPause 对 stopped/completed 状态走 `playHymn` 重载（resume 无效）。
  - `windows/flutter/generated_plugin_registrant.cc` / `generated_plugins.cmake`：插件注册由 just_audio_windows 换成 audioplayers_windows（构建自动生成）。
- **验证方式**：`flutter pub get`（解析 audioplayers 6.8.1 + audioplayers_windows 4.4.1）；`flutter analyze` 0 issues；`flutter build windows --release` 成功（95.4s）；启动 exe 用户确认**声音正常播放**。
- **遇到的困难**：audioplayers 6.x 的 `onLog` 流元素是 `String` 而非带 `level/message` 的对象，首版引用 `LogLevel` 导致 3 个编译错误——移除 onLog 错误检测（错误由 `play()` 抛 Future 异常捕获）后通过。
- **遗留问题**：人声版多版本切换发声未实测；state.json 持久化跨会话恢复联动未验证。

- 本次共处理 **3 个任务**（第 4 轮续接 / audioplayers 根治无声与 v1.0.0 / 补写会话日志）
- 关键收获：
  1. **audio_service 换芯最佳实践**：对外接口（status/position/currentHymn/playlist）不变的前提下，播放后端可从 just_audio 无缝切到 audioplayers——UI 层零改动，只需重写服务内部实现。
