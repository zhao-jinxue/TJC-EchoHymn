## 任务 1：将千问 API key 写入规则文件

### 提问

用户提供千问 API key（`sk-ws-H.ERYHIXX...`），要求将其写入"全局规则"中——遇到需要解析或理解图片的工作时，使用此 key 访问千问 API。

后续追问：

1. "写入那个文件了？"——要求明确 API key 实际落盘到哪个文件，而不是只在会话中生效。
2. "Cline 有一个全局规则文件，启动会话的时候，你有添加这个全局规则吗？"——要求确认 Cline 的全局规则文件机制，并确认全局规则已添加（而非仅项目级）。

### 解决思路

- 第一步尝试用 memory MCP 知识图谱存储 key（创建 `千问_API_KEY` 实体 + `图片解析` 实体 + "使用"关系），确实写入成功，但知识图谱的本质是"会话间可查询的记忆"，不是用户可编辑的明文配置，且其数据文件位置在本机无法直接定位。
- 用户追问落盘文件后意识到：要让 key 在**任何新会话**自动可用，必须写入 Cline 的规则文件体系。经排查确认存在两层：
  - **项目级** `e:\EchoHymn\.clinerules`：Cline 启动会话时自动注入系统提示（本会话系统提示中已含该文件内容，可直接验证）。
  - **全局级** `C:\Users\小蔡爱金雪\.clinerules`：用户主目录下的全局规则，对所有项目、所有工作区生效。
- 选定方案：**双写**——项目级与全局级各写一份「千问 API Key（图片解析/理解）」章节，memory 知识图谱作为备份层保留。

### 最终结果

- **完成结论**：千问 API key 持久化到两层规则文件 + 记忆知识图谱备份，未来任何会话遇到图片解析/理解任务时可直接使用。
- **关键改动**：
  - `e:\EchoHymn\.clinerules`：新增「千问 API Key（图片解析/理解）」章节（key、服务商 DashScope、调用方式 base URL、触发条件）。
  - `C:\Users\小蔡爱金雪\.clinerules`：文件末尾追加同一章节，并注明"本规则为全局规则，对所有项目、所有工作区生效"。
  - memory MCP 知识图谱：`千问_API_KEY`（APIKey 类型，观察含 key/服务商/用途）、`图片解析`（Task 类型）、关系 `图片解析 -使用-> 千问_API_KEY`。
- **验证方式**：
  - 系统提示 `USER'S CUSTOM INSTRUCTIONS` 部分显示项目级 `.clinerules` 已自动注入当前会话——规则生效的直接证据。
  - `read_graph` 确认记忆图谱保存成功。
  - 读取全局 `.clinerules` 全文确认追加成功。
- **遇到的困难**：memory MCP 首次 `create_entities` 报 JSON 解析错误（key 含特殊字符导致多行格式解析失败），改紧凑单行 JSON 后成功；memory 数据文件位置经多轮搜索（`~/.mcp-memory`、`%APPDATA%\mcp-memory`、用户目录递归）均未定位，最终明确以规则文件为主持久化载体。
- **遗留问题**：全局 `.clinerules` 的千问章节需在**下次启动新会话**时才会注入系统提示（本次会话仅项目级规则生效）；qwen-vl 实际调用未在本会话执行，待未来图片任务触发验证。
