## 任务 4：是否需要安装 CMake / 加入 PATH

### 提问

"之前分析过程中发现 CMake 不在 PATH 中，我需要安装CMake，或者将cmake添加到 path 中吗？"

### 解决思路

- 区分两条构建路径：`flutter build windows` 由 Flutter 自动定位 **VS 内置 cmake**（不依赖 PATH）；而 native 的原生 DLL 构建命令 `cmake -S . -B build` **需要 PATH 中有 cmake**。而项目的 FFI 架构依赖 `hymn_engine.dll`，故必须保证命令行 cmake 可用。
- 方案对比：A. winget 装独立 CMake（推荐，自动进 PATH）；B. VS 内置 CMake 目录加 PATH（零下载）；C. VS Code CMake Tools 插件。用户选 A 并要求装到 D 盘。
- 执行 `winget install Kitware.CMake --override "/quiet INSTALLDIR=D:\CMake"` → **失败 1603**；诊断根因：当前 shell 非管理员（`IsAdmin=False`），MSI 写 HKLM 注册表被拒。
- 改走免安装 ZIP：GitHub 直连极慢（~12–16 KB/s，51MB 预计 1h+）→ 清华 GitHub 镜像该仓库 404 → cmake.org 官方源同样慢（超时）→ **最终发现清华 PyPI 有 CMake 官方 wheel**（`cmake-4.4.2-py3-none-win_amd64.whl`，国内 CDN 快）。
- 自动下载被用户拒绝，改为交付手动教程（用户倾向自己操作）。

### 最终结果

- **完成结论**：CMake 必须可用；向用户交付无需管理员权限的手动方案。
- **关键改动**：新增 `docs/INSTALL_CMAKE.md`（三方案：**VS 内置 CMake 加 PATH【首选，零下载】** / 清华 PyPI wheel 解压到 D:\CMake / pip install --user；FAQ 含 1603 根因、镜像选择等）。
- **验证方式**：实测下载源可达性（GitHub/cmake.org 慢、清华 GitHub 404、清华 PyPI 200）。
- **遇到的困难**：非管理员导致 winget MSI 失败；出国带宽极慢迫使探索国内镜像。
- **遗留问题**：cmake 是否按方案一落地待用户执行（任务 6 中确认已落地）。
