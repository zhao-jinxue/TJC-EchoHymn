## 任务 1：感知 Flutter 已安装并修复镜像源 TLS 故障

### 提问

用户：开发环境（Flutter + C++）已经准备好了，你是否可以感知到（Flutter 已手动安装）？

### 解决思路

- 现象：`flutter --version` 首次执行卡在 `Building flutter tool...`，反复报 `Got TLS error trying to find package xxx at https://pub.flutter-io.cn`，重试 10 次后放弃。
- 根因排查：检查环境变量发现 `PUB_HOSTED_URL=https://pub.flutter-io.cn`、`FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`（中国镜像源）。用 `curl` 探测：官方 `https://pub.dev` 返回 200 正常，镜像 `pub.flutter-io.cn` 返回 301 且 Dart TLS 栈握手不稳。
- 方案对比：
  - A. 永久改用户环境变量 → 影响其他项目偏好，暂不做；
  - B. 当前会话临时注入官方源环境变量 → 最小侵入、立即生效。选定 B。
- 选定方案：会话内设置 `PUB_HOSTED_URL=https://pub.dev`、`FLUTTER_STORAGE_BASE_URL=https://storage.googleapis.com`。

### 最终结果

- **完成结论**：确认 Flutter 3.44.8（stable）/ Dart 3.12.2 已安装可用；镜像 TLS 故障通过切官方源解决。
- **关键改动**：本任务无源码改动；确认 `flutter doctor`：Windows/Chrome ✅，Visual Studio ❌、Android SDK ❌（暂不可构建桌面/安卓包）。
- **验证方式**：切源后 `flutter --version`、`flutter doctor` 立即正常，无 TLS 重试。
- **遇到的困难**：PowerShell 嵌套命令中 `$env:` 被提前插值导致赋值失败；改为当前会话直接设置后成功。
- **遗留问题**：镜像源故障仅临时规避，用户环境变量未永久修改；后续新终端仍走镜像。

## 任务 2：修复 dart:ffi 在 Web 平台不可用的编译失败

### 提问

（续接）环境就绪后，先后构建 web 版验证应用，遇到编译错误。

### 解决思路

- 现象：`flutter build web --release` 报 `Dart library 'dart:ffi' is not available on this platform`，主因是 `hymn_engine_bindings.dart` 顶层 `import 'dart:ffi'` 被静态引入。
- 根因：原设计虽在 `HymnRepository` 有"回退到纯 Dart JSON"的逻辑，但 FFI 绑定文件在编译期就被整体拉入 web 目标，导致无法编译。
- 方案对比：
  - A. 用条件导入（`if (dart.library.ffi)`）把 C++ FFI 实现与纯 Dart 实现分离 → 编译期按平台选择，最干净；
  - B. 去掉 FFI 依赖、全部走 Dart 解析 → 丢失 C++ 引擎能力；
  选定 A。
- 实施：新建 `engine_adapter_stub.dart`（基类，纯 Dart JSON 解析）、`engine_adapter_native.dart`（子类 `NativeEngineAdapter`，封装 C++ FFI 引擎）、`engine_adapter.dart`（条件导入门面），并重构 `hymn_repository.dart` 按平台使用适配器。
- 连带修复 `flutter analyze` 报出的：just_audio 0.9.46 的 `PlaybackEvent.playing` 已移除（改用 `_player.playing`）；若干 unused import / unused field / const 建议；`HymnRepository.usingCppEngine` 用 `runtimeType` 判断误报（改用 `adapter.isNativeEngine`）。

### 最终结果

- **完成结论**：`flutter analyze` 零错误，`flutter build web --release` 成功。
- **关键改动**：
  - `lib/services/engine_adapter.dart` / `engine_adapter_stub.dart` / `engine_adapter_native.dart`（新增，条件导入适配层）
  - `lib/services/hymn_repository.dart`（改用适配器；`usingCppEngine` 修正）
  - `lib/services/audio_service.dart`（`PlaybackEvent.playing` → `_player.playing`）
  - `lib/widgets/lyrics_view.dart`、`player_bar.dart`、`hymn_list_panel.dart`、`lib/screens/home_screen.dart`（清理 analyze 警告）
- **验证方式**：`flutter analyze`（No issues found）；`flutter build web --release`（Built build\web）；本地起 `python -m http.server 8000` 用 Playwright 访问——页面标题 "EchoHymn · 赞美诗与颂歌"、`hymns.json` 200、console 零错误。
- **遇到的困难**：headless 浏览器无 GPU 时 CanvasKit 未提交首帧画布（`flt-glass-pane` 为空但 WebGL 可用），判定为环境限制而非代码问题。
- **遗留问题**：Android 原生目录未集成 C++ 引擎（当前自动回退 Dart 解析，功能完整）。

## 任务 3：打包与迁移部署方案

### 提问

用户：既然 Flutter 开发环境已经具备，那么开发好的程序，怎么进行打包，然后迁移到相同系统的设备上，能够继续使用？

### 解决思路

- 环境约束：`flutter doctor` 显示本机未装 Visual Studio 与 Android SDK，因此**只有 Web 版可立即打包迁移**；Windows 桌面版、Android 版需补齐工具链。
- 方案：产出三平台打包迁移指南 + Web 一键打包脚本（版本化绿色包，目标机只需 Python）。
  - Web：`flutter build web --release` → 静态文件 zip；含 `start_web.cmd`（自动找 python 起本地服务器）与「开始使用.bat」。
  - Windows：需 VS + 开发者模式 → CMake 构建 C++ 引擎 → `flutter build windows` → 整体拷贝 Release 目录。
  - Android：需 Android Studio + SDK → `flutter build apk` → 直接安装。

### 最终结果

- **完成结论**：打包迁移方案落地，Web 迁移包实际生成。
- **关键改动**：
  - `docs/DEPLOY.md`（新增，三平台打包迁移指南 + 常见问题）
  - `tools/package_web.ps1`、`tools/打包.bat`（新增，一键生成 Web 绿色迁移包）
  - `README.md`（加入「打包与迁移」章节）
- **验证方式**：`pwsh -File tools/package_web.ps1` 成功生成 `release/echohymn-web-1.0.0.zip`（含 CanvasKit、中文字体、启动脚本）。
- **遇到的困难**：中文脚本在 Windows PowerShell 5.1 下 UTF-8 解析报"字符串缺少终止符"，改用 PowerShell 7（pwsh）执行成功。
- **遗留问题**：Windows/Android 版打包依赖后续安装 VS 与 Android Studio。

## 任务 4：git commit 后自动打包发布（版本目录仅保留最近 5 份）

### 提问

用户：实现每次 git commit 操作之后，就进行打包发布，形成新的程序版本，版本目录只保存最近 5 次发布的版本。

### 解决思路

- 方案：git `post-commit` 钩子 + 发布流水线脚本。
  - 钩子：每次 commit 成功后**后台异步**执行发布脚本（避免阻塞 commit），并将日志写入 `release/auto-release.log`；仅 `master/main` 分支触发。
  - 流水线 `publish_release.ps1`：构建 Web → 调 `package_web.ps1` 版本化打包 → 按创建时间倒序清理，仅保留 `KeepCount`（默认 5）份版本目录。
  - 版本目录命名：`release/echohymn-web-<短commit>-<时间戳>/`。
- 遇坑与修正：初版钩子是无扩展名 `.bat` 内容，Git for Windows 无法执行导致钩子未触发；改为 `#!/bin/sh` 的 Git Bash 脚本（Git for Windows 自带 sh）后正常。

### 最终结果

- **完成结论**：实现并验证"每次 commit 自动打包发布 + 只保留最近 5 版"的完整闭环。
- **关键改动**：
  - `tools/publish_release.ps1`（新增，发布流水线：构建→打包→清理保留 5 版）
  - `tools/git-hooks/post-commit`（新增，sh 钩子模板，后台启动流水线）
  - `tools/install_hooks.bat`（新增，一键安装钩子到 `.git/hooks/`）
  - `tools/package_web.ps1`（改造为版本化输出目录）
  - `README.md` / `docs/DEPLOY.md`（新增自动发布说明）
- **验证方式**：
  - 手动执行流水线 → 生成 `echohymn-web-744395c-...`；
  - 空提交 `0e7971c` → 钩子自动发布成功（日志完整）；
  - 制造 9 个版本再发布 → 自动删除 4 个最旧版，精准保留 5 个；
  - 最终提交 `013fd0b` → 钩子自动生成 `echohymn-web-013fd0b-220733`（保留 4 版）。
- **遇到的困难**：钩子文件无扩展名 bat 不被 Git 识别；PowerShell 中 `copy` 被解析为别名；均改用正确工具（sh 脚本 / Copy-Item）解决。
- **遗留问题**：发布 zip 同时被纳入 git 仓库（`release/` 未忽略），后续可评估是否在 `.gitignore` 排除以减小仓库体积。
