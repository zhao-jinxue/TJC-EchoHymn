## 任务 2：排查"终端不加载 Profile"问题并建立 PATH 修复机制

### 提问

用户两次追问：①「为什么你的终端启动的时候，不会继承系统的 Profile，这是否可以优化？」②「你的终端启动的时候，是否可以设置环境变量？」③ 对反复手写三行的做法不满，希望"一次获得、多次使用"。

### 解决思路

- 根因定位：读取注册表 Machine/User PATH 后发现，Git 与 Python 路径**都已正确配置**在系统/用户级 PATH 中；真正的差异是**工具进程继承的 PATH 被宿主（VS Code）精简**，仅剩 VS Code 专用目录——并非 Profile 未加载。
- 方案对比：① 每次内联三行合并 PATH（啰嗦）；② `settings.json` 硬编码（需手动维护、不跟随系统变化）；③ **固化脚本 + 点引用**（一行调用、一处维护、注册表实时读取）；④ PowerShell Profile 自动加载（用户终端开箱即用）。
- 选定③+④组合：脚本 `Fix-Path.ps1` 固化为唯一逻辑源，Cline 侧命令前点引用，用户侧 Profile 自动加载。

### 最终结果

- **完成结论**：PATH 修复机制固化完成，git/python 可被直接调用。
- **关键改动**：
  - 新增 `C:\Users\小蔡爱金雪\.cline\scripts\Fix-Path.ps1`（合并 Machine+User PATH 到 `$env:Path`）
  - 新增 `C:\Users\小蔡爱金雪\Documents\PowerShell\Microsoft.PowerShell_profile.ps1`（自动点引用 Fix-Path）
  - 全局规则 `C:\Users\小蔡爱金雪\.clinerules`：登记 PATH 修复规则 + 「优先使用 Python」偏好
- **验证方式**：点引用后 `git --version`=2.55.0、`python --version`=3.13.14 均直接可用；新进程加载 Profile 后无需修复代码直接调用成功。
- **遇到的困难**：最初误以为是 Profile 未加载，实测证明是 PATH 继承链问题，需区分 `python`（别名拦截）与 `py`（启动器可用）。
- **遗留问题**：settings.json 硬编码方案不采用（需手动维护），改由 Profile 动态合并兜底。

### 最终结果

- **关键改动**：
  - 新增 `C:\Users\小蔡爱金雪\.cline\scripts\mcp_check.py`（解析配置→启动进程→initialize 握手→汇总报告）
  - 修复 `cline_mcp_settings.json`：filesystem 路径 `/home/zjx`（Linux 遗留）→ `E:\EchoHymn`
- **验证方式**：检测输出 fetch-mcp 0.0.5、secure-filesystem-server 0.2.0、memory-server 0.6.3、Playwright 1.62.0、sequential-thinking 0.2.0、proxy-web-mcp 1.0.0 全部 PASS。
- **遇到的困难**：① 首次全部 WinError 2（npx.cmd 问题，cmd 包装解决）；② filesystem 因 Linux 路径无效而拒绝启动（改 Windows 路径解决）。

## 任务 4：MCP 配置优化——全局与项目级拆分

### 提问

用户质疑：全局配置 `cline_mcp_settings.json` 中写死 `E:\EchoHymn`，换项目岂不失效？该全局配置文件对所有项目生效，项目级路径不应写死其中。随后确认采用拆分方案。

### 解决思路

- 源码取证：检查 Cline 扩展（saoudrizwan.claude-dev-4.1.4）`extension.js`，确认存在 **项目级 `.mcp.json`** 支持（schema 含 `enabledMcpjsonServers: "List of approved MCP servers from .mcp.json"`）与 `workspaceFolder` 可选字段。
- 选定架构：全局配置只保留通用服务器（fetch/playwright/sequential-thinking/memory/web-bridge）；**filesystem 移入项目级 `.mcp.json`**，路径写死为项目固定目录。
- 用户后续追加意见：项目级配置中无需 `${workspaceFolder}` 变量，直接写固定路径，避免浪费解析开销。

### 最终结果

- **完成结论**：MCP 配置完成「全局通用 + 项目级绑定」拆分，换项目零冲突。
- **关键改动**：
  - 新增 `E:\EchoHymn\.mcp.json`（filesystem → `E:\EchoHymn`，固定路径）
  - 修改全局 `cline_mcp_settings.json`（移除 filesystem，保留 5 个通用服务器）
- **验证方式**：源码检索确认 `.mcp.json` 加载机制存在；配置文件 JSON 合法。
- **遇到的困难**：PowerShell 中 `${...}` 触发变量解析报错、Python 内联转义易失败，改脚本文件执行源码分析。
- **遗留问题**：Cline 需重启/重新加载后项目级 MCP 生效（检测程序已可复用验证）。
