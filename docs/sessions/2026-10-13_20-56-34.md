# 曲谱两项优化：多余声部音符行 + 记谱字号减半（v1.8.3）

- 日期：2026-10-13
- 工具链：Cline + DeepSeek API
- 涉及模块：曲谱渲染（`JianpuGridView`）· 简谱网格模型（`JianpuScore`）· 安装包发布（`installer/`）

## 任务 1：修复「首/末歌词行上下各多出一行简谱」

### 提问

（用户）截图 `ScreenShot_2026-10-13_204024_140.png`（第 1 首《颂赞独一真神》曲谱第 1/3 节）：
**第一行歌词和最后一行歌词，有两行简谱**（中间的歌词行只有一行）。

### 解决思路

1. **先看数据再看图**：dump 第 1 首的行结构 → 每块 = `note, note, mark_down, 歌词×3, mark_up, note, note, mark_down`
   （共 4 个块同构）。
2. **用印刷本交叉验证**（`data/Hymn_Downloads/001_1頌讚獨一真神/1_简谱.png`）：
   该首是**四声部**排版 —— **S、A 两行在歌词上方，T、B 两行在歌词下方**，
   所以 CSV 的块内布局是「两声部 + 歌词 + 两声部」。
3. **定位旧实现的缺陷**：`_firstVoiceRows` 按「遇到 `mark_down` 即第一声部组结束」判组；
   第 1 首的 S 行**没有自己的下方记号行**，紧接着就是 A 行 → 判组条件不成立 → **A 行被一并保留**
   （T/B 两组倒是正确丢弃）→ 表现就是「首/末歌词行上方多一行简谱」。
4. **量化范围**（全库 474 首）：首组音符行 > 1 的块 **330 个 / 128 首**（不是个例）。
5. **方案取舍 —— 怎么判「哪行记号属于哪个声部」**：
   | 备选 | 结论 |
   | --- | --- |
   | 只留第一个音符行 + 紧邻前后的记号行 | 会丢掉「夹在 S 与 A 之间、属于 S 的低音点行」（第 111 首全曲如此）✗ |
   | 只留第一个音符行（记号全不要） | 同上，且连 S 自己的低音点/减时线也没了 ✗ |
   | **按字形归属**：`D`（低八度点）/`B`（减时线）属**上方**声部；`U`（高八度点）/`E`（延长记号）属**下方**声部 | ✅ 选定：第 111 首 `MDN` 行保留、第 9/102 首 `MUDN`/`MEN` 行丢弃，与印刷本一致 |
   - ⚠️ 关键坑：**不能用 `dots` 字段判**（高八度点字形 `MUDN` 里也含字母 `D`）→ 必须用字形字母串
     并**排除同时带 `U` 的**。

### 最终结果

- **完成结论**：第 1 首曲谱每块只剩 **1 个音符行**（S），歌词上下不再多行；全库同类 128 首一并修正。
- **关键改动**：`hymn_app/lib/models/jianpu_grid.dart` → `_firstVoiceRows` 重写
  （保留 = 全部歌词行 + 第一个音符行 + 其上方紧邻记号 + 与下一音符行之间含**下标记号**的行）
  + 新增 `_hasDownMark`（字形判据）；`test/jianpu_grid_test.dart` 新增纯模型用例（第 1/111/102 三种形态）；
  `test/jianpu_golden_test.dart` 新增 `jianpu_001_stanza1.png` 快照（并断言每块仅 1 个音符行）。
- **验证方式**：`flutter analyze` 0 issues；`flutter test` **61 通过**；
  全库量化：**330 块 / 128 首**受影响、**音符行净减少 146 行**、无歌词行受影响；
  golden 目视核对（新快照每行歌词上方只有一行简谱）。
- **遇到的困难**：第一版用 `dots > 0` 判「下标记号」→ 单测立刻暴露（第 9/102 形态的高音点行被误留）；
  改用字形字母串并排除 `U` 后三种形态全部正确。
- **遗留问题**：无。

## 任务 2：论证并落地「记谱字号 = 歌词视觉大小的一半」

### 提问

（用户）截图 `ScreenShot_2026-10-13_204043_046.png`（第 2 首《赞美圣父》）：
**简谱的字号和简谱下方的点横字号，与歌词的字号是等同的，导致整体视觉效果上歌词变小了**；
先论证「在保持词谱对齐的情况下，简谱字号与点横字号能否做到只有当前歌词字号的一半」，
可以的话就调整简谱、点横、以及**简谱竖线**的字号。

### 解决思路（论证）

**① 度量事实（两个来源，可复算）**：
- 记谱字体数字字形墨迹高（`lib/data/jianpu_metrics.dart`，1~7 码位）
  = **0.3354 ~ 0.3674 em，均值 0.3447 em**；墨迹宽均值 0.2167 em；
- 楷体汉字墨迹高（golden 快照像素实测）= **0.766 em**；
- 现有版式：记谱字号 = **1.0 × 槽宽**、歌词字号 = **0.54 × 槽宽**
  → 音符墨迹 **0.345** 槽宽 vs 歌词墨迹 **0.414** 槽宽 = **83 %**
  → **快照像素实测：音符行墨迹 15 px vs 歌词行墨迹 18 px**（= 用户所说「等同」）。

**② 能否「保持对齐」地做到一半？—— 能，而且只有一条路**：
- 列宽（拍点间距）与歌词字号都必须**不动**（对齐 = 同列同 x，且歌词字宽 ≈ 1 em 歌词字号
  必须 ≤ 1 列宽，否则相邻歌词字会挤在一起）→ 歌词**不能再放大**；
- 于是只能**缩小「每列内字形占多大」**：即把记谱字号从 1.0 槽宽降到 0.6 槽宽。
  → 记谱字号与槽宽**解耦**是唯一可行解，且完全不影响列位置（同列仍同 x）。

**③ 系数取值**：要求「音符视觉大小 = 歌词的一半」→
`0.3447 × f = 0.5 × (0.54 × 0.766)` → **f = 0.600**（取整 0.60）。

### 最终结果

- **完成结论**：可行且已落地。记谱字号系数 **0.60**，点横/八度点/延长记号/小节线宽度同步按此系数缩放；
  歌词字号、列宽、同列对齐**均未变**。
- **关键改动**：`hymn_app/lib/widgets/jianpu_grid_view.dart`
  - 新增 `noteFontEm = 0.60`（含论证注释）+ `_Metrics.noteSize = slot × noteFontEm`；
  - 音符/休止/增时线/附点字形、变音记号、八度点直径、减时线（宽 + 厚）、延长记号框、
    **小节线宽度**（`barW`）全部改用 `noteSize`；
  - 行高改为「音符/记号行 = noteFontEm × 原系数」（1.34/0.50/0.58 → 0.80/0.30/0.35 槽宽）；
  - 歌词行高、歌词字号、列宽、`minSlot/maxSlot` 不变。
- **验证方式**：
  - `flutter analyze` 0 issues；`flutter test` **61 通过**（含新增「记谱字形 ≈ 歌词视觉大小的一半」断言：
    用墨迹度量表复算，比值 0.50 ± 0.05）；
  - **快照像素实测**（同一张 `jianpu_283_stanza3.png`）：音符行墨迹 **15 px → 9 px**、
    歌词行 **18 px → 17.5 px** → 视觉比 **83 % → 51 %** ✓ 正好一半；
  - golden 5 张重生成 + 目视核对（歌词明显主导、记谱未糊）。
- **遇到的困难**：无。
- **遗留问题 / 可调项**：
  1. 若希望记谱「再小一点/再大一点」，只改 `noteFontEm` 一个常量即可（0.5 → 比值 42%，0.7 → 59%）；
  2. 记谱变小后整页纵向更宽松（内容仍整块垂直居中）→ 若要把留白用起来，
     可后续把**歌词字号**上限从 0.54 槽宽提到 ~0.9 槽宽（仍在 1 列宽内，不破坏对齐）—— 本次未做（用户未要求）。

## 会话总结

- 本次共处理 **2 个任务**（① 修复首/末歌词行多余声部音符行；② 论证并落地记谱字号减半）。
- 关键收获：
  1. **「多出来的一行」要用印刷本定案**：dump 数据只能看出「块内有两个音符行」，
     查印刷图才确认那是 S/A 两声部（所以只该留 S）—— 数据 + 印刷本互证是本案的关键一步；
  2. **字形字母串能区分「点属于哪个声部」**：`D`=低八度点（属上方声部）、`U`=高八度点（属下方声部），
     而 `dots` 字段把两者都记成 1 → **不能用来判断**（第一版就踩了这个坑，被单测挡住）；
  3. **「字号减半」要先定义量的是 em 还是墨迹**：两字体墨迹占比不同（记谱 0.345 em / 楷体 0.766 em），
     按「视觉（墨迹）」减半 → 记谱字号系数 0.60，而**不是**按 em 直译的 0.27；
     论证同时给出「为什么只能缩记谱、不能放大歌词」（歌词字宽 ≤ 1 列宽的硬约束）。
- 遗留事项：见任务 2 的可调项（`noteFontEm` 单常量可调；歌词字号上限可另行放宽）；v1.8.3 安装包待重出。
