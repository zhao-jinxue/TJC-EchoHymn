用户先确认「全局规则和项目规则，加载了？」；随后指出：只是做了简单的提问就消耗了 122.2k 上下文，询问为什么、是否还可以优化。

### 解决思路

| 节点 | 上下文 | 增量 |

结论：三个文件加 git log 只增加约 8k，剩余约 114k 是会话一开始就由系统提示注入的——其中 **7 个 MCP 服务器的完整工具定义约 100k** 是绝对大头（powerpoint / xmind 每个都带几十个工具的完整 JSON Schema），即使本次任务完全用不到也全量计入每次请求。

### 最终结果

- **验证方式**：三次启动流程工具调用的累计上下文实测数据。
- **遇到的困难**：无。
- **遗留问题**：提出两套优化方案（A. MCP 按需加载 / B. 精简常驻服务器），待用户选择后落地。

## 任务 2：精简 MCP 常驻服务器（方案 B）

### 提问

用户选择方案 B「精简常驻服务器」，期望把平时不用的服务器从常驻中移除，降低上下文开销。

### 解决思路

先读项目级 `.mcp.json`，发现只有 `filesystem` + `memory` 两个且均未全量注入，说明实际注入的 7 个服务器来自**全局 MCP 配置**。扫描用户主目录定位到两份同名的全局 `cline_mcp_settings.json`：

1. `C:\Users\小蔡爱金雪\.cline\cline_mcp_settings.json`（CLI/传统形态）
2. `C:\Users\小蔡爱金雪\AppData\Roaming\Code\User\globalStorage\saoudrizwan.claude-dev\settings\cline_mcp_settings.json`（VS Code 扩展）

两份均含 fetch / playwright / sequential-thinking / memory / web-bridge / powerpoint / xmind 七个定义。按方案 B 统一将**非保留服务器 `disabled: true`**，仅保留 `fetch`（网页抓取）+ `memory`（知识图谱记忆）两个轻量常驻。

### 最终结果

- **完成结论**：全局 7 服务器精简为 2 个常驻；重启后系统提示仅注入 fetch + memory，会话基础上下文从约 130k 降至约 20k（约为原来的 1/5）。
- **关键改动**：
  - `C:\Users\小蔡爱金雪\.cline\cline_mcp_settings.json`（sequential-thinking / web-bridge → disabled: true）
  - `C:\Users\小蔡爱金雪\AppData\Roaming\Code\User\globalStorage\saoudrizwan.claude-dev\settings\cline_mcp_settings.json`（playwright / sequential-thinking / web-bridge / powerpoint / xmind → disabled: true）
- **验证方式**：修改后重启 Cline，新会话 `Context Window Usage` 首条即 33k（此前 114k+），MCP 工具列表只剩 fetch 与 memory——精简生效。
- **遇到的困难**：终端输出捕获不稳定（中文路径导致 PowerShell 截断），多次改用「重定向到文件再读取」的方式完成排障。
- **遗留问题**：当前会话的工具列表是启动时快照，旧会话不动态移除；需重开会话生效。

## 任务 3：确认全局配置只保留一份 + 其他 MCP 按需启用可行性

### 提问

用户追问两点：Q1——全局 MCP 配置是否可以只保留一份，保留 `C:\Users\小蔡爱金雪\.cline\cline_mcp_settings.json` 这份？Q2——MCP 常驻服务器已精简，其他 MCP 在需要使用的时候是否还能正常加载并使用？

### 解决思路

为得到确凿答案，深入 Cline VS Code 扩展源码（`next/dist/extension.js`，rollout 机制确认实际 bundle 为 next）逐行验证配置文件加载逻辑：

- `getMcpSettingsFilePath(t) = join(t, "cline_mcp_settings.json")`（配置文件名固定）
- 实际读取处 `readAndValidateMcpSettingsFile()` 调用 `tk(await this.getSettingsDirectoryPath())`
- `getSettingsDirectoryPath` 基于 VS Code 的 `globalStorageFsPath` → 指向 `...\globalStorage\saoudrizwan.claude-dev\settings\`

源码证据链说明：**VS Code 扩展实际只读取 globalStorage 下那份**；`C:\Users\小蔡爱金雪\.cline\cline_mcp_settings.json` 属于 CLI/传统形态路径（同目录下还有 `data/`、`bin/`），VS Code 扩展并不读取。

因此：Q1 可只保留一份（删 CLI 副本，保留 globalStorage 那份）；Q2 可正常按需启用——`disabled: true` 仅表示不注入工具定义，配置完整保留，在 Cline 的 MCP 管理面板点击启用或改 JSON 的 `disabled` 为 `false` 保存即自动重载，启用后才占用上下文。

### 最终结果

- **完成结论**：Q1 已按用户选择删除 `C:\Users\小蔡爱金雪\.cline\cline_mcp_settings.json`，全局只保留 VS Code globalStorage 一份；Q2 确认 disabled 服务器可随时在 MCP 面板一键启用，按需加载、平时零开销。
- **关键改动**：
  - 删除 `C:\Users\小蔡爱金雪\.cline\cline_mcp_settings.json`
  - 保留 `...\globalStorage\saoudrizwan.claude-dev\settings\cline_mcp_settings.json`（仅 fetch + memory 启用）
  - 源码级确认（无改动）：`next/dist/extension.js` 的 `getMcpSettingsFilePath` / `getSettingsDirectoryPath` 逻辑
- **验证方式**：`Get-Item` 对比两份文件；`Remove-Item` 后 `Test-Path` 确认删除成功；清理临时探测文件 `mcp_probe.txt`。
- **遇到的困难**：大文件源码（`next/dist/extension.js` 单文件过大无法直接读入）需用 PowerShell `Select-String` + 行号截断再落盘读取的方式定位关键函数，过程较长。
- **遗留问题**：项目级 `.mcp.json` 中的 `filesystem` 服务器未被注入（不在系统提示中），如需彻底清理可后续处理。

## 会话总结

- 本次共处理 **3 个任务**（上下文消耗根因分析 → 精简 MCP 常驻服务器 → 唯一配置落地与按需启用确认）
- 关键收获：
  1. **上下文消耗的构成认知**：简单提问却消耗 122k 的根因不是工具使用，而是系统提示常驻的 MCP 工具定义（约 100k）；精简常驻服务器后单会话基础开销降为约 1/5

- 遗留事项：
  - 项目级 `.mcp.json` 的 `filesystem` 服务器未实际注入，可选清理
  - 后续如需 PPT / 思维导图 / 浏览器自动化，在 Cline MCP 面板启用对应服务器即可，无需改文件
