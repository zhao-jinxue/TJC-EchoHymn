# 曲谱「有副歌的曲子没词」修复（v1.8.1）

- 日期：2026-10-12
- 工具链：Cline + DeepSeek API
- 涉及模块：曲谱渲染（`JianpuGridView`）· 简谱网格模型（`JianpuScore`）· 安装包发布（`installer/`）

## 任务 1：修复「曲谱显示模式下有副歌部分的曲却没有词」并发布 v1.8.1

### 提问

（用户）截图 `ScreenShot_2026-10-11_161239_019.png`：Windows 版**曲谱**模式（一页一节）下，
**有副歌的曲子却没有词**——第 283 首《为主收庄稼》第 3/3 节页面上，副歌所在的后两块只有谱行、
整块无词。要求：修复该 bug → 自检 → 提交并推送 → 发布安装包。

### 解决思路

**① 先证伪「数据缺失」，再定位是渲染规则问题**（不猜、先取证）：

- 查 `jianpu_row` / `jianpu_cell`（第 283 首）：4 个块 —— 块 0/1 各 **3 行歌词**（正歌，带 `(1)(2)(3)` 节号），
  块 2/3 各 **1 行歌词**（副歌两句，节号列只有 `(1)`）；数据库 `jianpu_score.stanza_count = 3`。
  **副歌的歌词数据是齐的**，只是逐节过滤时被整块滤掉。
- 读代码定位：`JianpuGridView._visible` 的判断是 `row.stanzaNo == stanza` ——
  块 2/3 的行节号是 1，页 2/3 自然一行都不显示（页 1 能显示，所以此前没被发现）。
- 抽回原始 APK `com.tinanlin.tjc_hymn_cn_v2.4.2.apk` 的 `assets/283.csv` 与 `111.csv` 核对：
  **印刷本对副歌只写一遍**（行上只有 `(1)`），且第 111 首首块 **每行都印 `(1)`** ——
  证实「行上节号 ≠ 该行所属节」，**不能作为逐节过滤的唯一依据**。

**② 全库量化，把规则建立在数据事实而非个例上**（474 首逐首统计）：

| 事实 | 数值 |
| --- | --- |
| 含「块内歌词行数 < 全曲节数」的诗歌（= 副歌 / 各节共用句块） | **280 首 / 584 块** |
| 此类块的单行节号取值 | 全部为 1（顺序编号），无例外 |
| 「块内歌词行数 > 节数」的诗歌（= 块内还有**重复句行**，如第 18 首块 2 共 6 行 = 3 节 + 3 行句尾重复） | 25 首 |
| 数据库 `stanza_count` 与该 25 首真实节数不符（被重复句虚增，如 18 首 3→记成 6） | **25 首** |
| 首块每行都印 `(1)`（节号不可信） | 第 111 首 |

**③ 方案取舍**：

| 议题 | 备选 | 选定 | 理由 |
| --- | --- | --- | --- |
| 副歌块怎么判 | ① 用 `tjc_hymn.chorus` 文本匹配；② 写死「最后 N 块」；③ **结构判据：块内歌词行数 < 全曲节数** | ③ | ②依赖版式假设；①文本受繁简/标点/缩写影响（实测 103 首副歌第二句印刷为缩写「呼唤你呼唤你」）；③纯结构、全库可验证（280 首 100% 命中且无假阳性） |
| 行归节依据 | ① 行上节号；② **行在块内的位置** `((i-1) mod 节数)+1` | ② | 第 111 首节号不可信；重复句按位置正好归回对应节（18 首实测吻合） |
| 真节数从哪来 | ① 数据库 `stanza_count`；② `verse_count`；③ **带 `(k)` 节号的行数** | ③ | ①被重复句虚增（25 首）；②第 399 首 = 7 而 CSV 只有 4 节；③只看**行数**不看取值 → 第 111 首仍得 3，且无节号时可回退「块内最大歌词行数」（仅第 460 首走回退，行为与库值一致） |
| 改动落点 | 视图内联 / **模型 + 视图分工** | 分工 | 模型（`JianpuScore._deriveStanzaCount`、`JianpuBlock.sharesLyricsAcrossStanzas`）出「数据语义」，视图（`_visibleRows`）只做渲染过滤 → 可单测、`hymn_display` 零改动 |

**④ 风险控制（防止「修好一处、弄坏别处」）**：写全库「修订前 vs 修订后」模拟脚本逐节比对，
输出三个数：页数变化、新增显示行、**仍在的页上被隐藏的行**（潜在回归唯一来源）。

### 最终结果

- **完成结论**：bug 已修复并验证——第 283 首第 3 节的副歌两句在页面上正常显示；
  连带修正同类问题的 21 首页数与 1 首错标节号丢词；全库无回归。
- **关键改动**：
  - `hymn_app/lib/models/jianpu_grid.dart`：新增 `JianpuRow.hasStanzaLabel`、
    `JianpuBlock.lyricCount` / `sharesLyricsAcrossStanzas(n)`、`JianpuScore._deriveStanzaCount()`
    （节数改由行数据推导，入参库值降为兜底）；`stanzaCount` 文档同步。
  - `hymn_app/lib/widgets/jianpu_grid_view.dart`：`_visible/_hasVisible` → **`_visibleRows(block)`**
    （非歌词行恒显示 → 副歌/共用块每节都显示 → 缺节号照旧显示 → 其余按行位置归节）；
    高度预算与渲染共用同一份可见行；节号 `(k)` 只在与当前节相符时渲染。
  - `hymn_app/test/jianpu_grid_test.dart`：新增 8 条用例（2 条纯模型 + 6 条实库：283/18/111/103）；
    顺带修正因 349 于 10-11 回到库内而**过期**的旧断言（`orphans == ['349']` → 空）。
  - `hymn_app/test/jianpu_golden_test.dart` + `test/goldens/jianpu_283_stanza3.png`：新增该页快照。
  - 版本 `1.8.0+1` → **`1.8.1+1`**；文档同步：`README.md`、`docs/README.md`、
    `docs/Windows/{SESSION_SUMMARY,UI_CONFIRMATION,SCORE_SELFTEST,CODE_REFERENCE}.md`。
- **验证方式**（全部实测，非推断）：
  - `flutter analyze` → **No issues found**
  - `flutter test` → **55/55 通过**（修订前 43 + 新增 8 + golden 计数变化）
  - `python tools/jianpu_csv_selftest.py` → **L0 行 21819 / 格 321703，行差异 0、格差异 0，PASS**
  - golden：`--update-goldens` 后**只有新增的 `jianpu_283_stanza3.png` 变化**，原 3 张未动
    （证 hymn 9/163 渲染未受影响）；用视觉模型复核该 PNG = 4 行歌词，含副歌
    「谨遵主命…」「伸出镰刀…」（`qwen3-vl-plus`；DeepSeek key 本机未配置）
  - 全库模拟：页数变化 **21 首**（仅减少虚增页，18 首 6→3、468 首 8→4 …）、
    新增显示 **1921 行 / 282 首**、**仍在页上被隐藏仅 2 行**（111 首首块第 2/3 行 → 已改在各自节显示）
- **遇到的困难**：
  1. 首次插入测试时误把锚点行 `test('空网格判定', () {` 当作替换目标而未回填 → 文件语法断裂。
     以 `flutter test` 的编译报错定位、补回该行后恢复（教训：`old_text` 锚点必须连同 `new_text` 一起保留）。
  2. `flutter analyze` 对新增测试报 2 条 `prefer_const_constructors` → 补 `const` 后回到 0 issues。
