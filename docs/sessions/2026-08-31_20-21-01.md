2. 想在**换肤按钮旁边**增加「切换字号」功能，分**四个等级**：默认 / 中号 / 大号 / 最大。
3. 用户明确要求：**先思考切换字号时会遇到哪些问题**，再动手。

### 解决思路

（详见会话正文的分析：8 类问题 + 三方案对比。）

**用户补充的关键决策（重新思考后定稿）**：

1. 歌词区单独处理，保持「铺满自适应字号」算法（基准），字号系数乘在最终 bodySize 上。
2. **其他所有区域**（含按钮文字）都适用新字号变更功能。
3. **图标跟随缩放**；所有控件尺寸/位置与字号建立等比例关系——字号变更 = 整树等比例缩放控件。
4. 保持最小客户区 850×890 不变。
5. 字号增大后左栏宽度不够时，允许**压缩歌词区宽度**（歌词区目前宽度空余多）。
6. 13px→19.5px（1.5×）范围可能不够，初版用可调常量，**"最大"字号初版后再定**。

**选定实现**：`FontScaleController`（ValueNotifier）+ `AppFonts` 语义门面

- `AppFonts.s(base)`：字号（按钮/列表/弹窗/菜单/Toast 全部走）
- `AppFonts.d(base)`：尺寸/间距/图标/栏高/面板宽（等比例缩放控件）
- 歌词区：`bodySize = 铺满自适应值 × 系数`（保留算法）
- 左/右面板宽度 × 系数，`_syncWindowSize` 传递缩放后宽度，歌词区 Expanded 自动让位（压缩）
- `state.json` 新增 `fontSizeLevel` 持久化

## 任务 2：系数调整（1.3/1.6/1.9）+ 右栏宽度固定 600 + 守卫自查

### 提问

1. 自查代码：连续点两次"大号"，第二次是放行还是拒绝？选完"最大"再选"大号"，是 ×1.6×1.4 还是 ×1.4？
2. 字号放大时**右栏宽度不用变**（有滚动条）；系数调整为 **中号 1.3 / 大号 1.6 / 最大 1.9**（若难算则 1.4/1.8/2.2）。
3. 清除临时中间脚本文件。

### 解决思路

1. **守卫自查结论（纯代码逻辑）**：两次点击"大号"→ 第二次被 `_switchFontSize`（`if (level == current) return`）和 `switchTo`（双重守卫）**拒绝**，系数固定不变；选完"最大"再选"大号" → `notifier.value = level` **覆盖式赋值**，`scale = current.scale` 读枚举固定常量 → **默认 ×1.4**（新系数下 ×1.6），绝无累乘路径。已用单元测试 `font_size_level_test.dart` 固化验证。
2. **系数**：1.3/1.6/1.9 是纯枚举常量，计算无难度 → 采用第一组。
3. **右栏固定 600**：全局 Transform 会把整树放大为 画布×系数，右栏宽度在画布内**反向缩放**（`600 / 系数 / dpr`）→ 视觉恒 600；`_syncWindowSize` 右栏 native 扩展也固定 600（左栏仍 350×系数）。

### 最终结果

- **完成结论**：系数调整为默认 1.0 / 中号 1.3 / 大号 1.6 / 最大 1.9；右栏宽度固定 600 不随字号缩放（源考文字放大后可滚动）；重复点击守卫行为经单元测试固化。
- **关键改动**：`lib/theme/app_fonts.dart`（系数）、`lib/screens/home_screen.dart`（`_buildRightPanel` 反向缩放 + `_syncWindowSize` 右栏固定）、`test/font_size_level_test.dart`（常量更新）、`UI_CONFIRMATION.md`/`SESSION_SUMMARY.md`/`v150_fontsize_test_cases.md`（文档同步）、`docs/sessions/`（本日志）
- **验证方式**：`flutter analyze` 0 issues；`flutter test` 3 项通过；`flutter build windows --release` 成功。
- **遇到的困难**：无
- **遗留问题**：待用户实机验收。

- 本次共处理 3 个任务（v1.5.0 字号功能 + 系数/右栏调整 + 测试后修 Bug/复测清单）
- 关键收获：
  1. **全局等比缩放用 `MaterialApp.builder` + `Transform.scale`**：一处实现全部控件/字号/图标缩放（含弹窗/菜单/Toast），远优于逐个改 54 处字号常量；结构沿用 v1.2.x 已验证的 `Align→Transform→SizedBox` 模式，命中测试正确。

  4. **字号守卫无累乘**：重复点击同等级被双重守卫拒绝；切任意等级后系数都是该等级枚举常量（覆盖式赋值），不存在 ×1.6×1.4 的路径。
