## 任务 1：Windows 版封版前的文档一致性校验与修订

### 提问

> 当前 Windows 版本的程序，已经比较满意了，目前还没有发现明显的 bug，所以暂时可以封版了。在封版之前还需要确认 `docs\Windows` 目录下的文档和实际情况是否吻合、是否有遗漏；`docs\README.md` 和 `README.md` 两个文档也需要校验，确保文档如实记录。

### 解决思路

**校验原则**：一切结论以**可复现的确定性证据**为准（`git log/tag`、`pubspec.yaml`、`hymn_app/lib/**`、`data/tjc_hymn.db` 实测 `count()`、`installer/output/` 实测字节数、`flutter test` 用例静态计数），**不采信文档之间的相互引用**；中文输出先 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` 避免 PowerShell 乱码误导（同类校验曾被乱码干扰）。

**分层判据**：
1. **版本类**：以 `hymn_app/pubspec.yaml`（单源）+ `git tag/log` 为准；
2. **功能/UI 类**：以 `lib/` 下的枚举/字段/组件为准（如 `DisplayMode`、`AppState` 字段、`win32_window.cpp` 托盘族）；
3. **数据类**：以 `sqlite3` 直查 `data/tjc_hymn.db` 表名与行数为准；
4. **产物类**：以 `installer/output/` 与 `release/echohymn_win_*/` 实际文件与字节为准。

**修订原则（沿用 2026-09-21 会话口径）**：**当前状态文档改事实、历史记录只追加指针**——`docs/sessions/**`、`BUGFIX_REPORT_2026-09-05.md`、`ruanzhu/workspace/**`、`UI_CONFIRMATION.md` §5.x 的演进条目属历史档案，只补「已停用/已删除」指针，不改写历史数字。

**取证清单（一次性并行）**：`docs/` 全量文件清单与各文档头部版本行；`git tag --format=%creatordate`；`git log --date=short`；`pubspec.yaml`；`lib/`/`test/` 树；`tools/` 实有脚本；`installer/output` 体积；SQLite 表名与行数；`DisplayMode` 枚举与版本栏文案；`AppState` 字段表；`win32_window.cpp` 托盘族；`user_manual_dialog.dart` 章节。

### 最终结果

- **完成结论**：完成三方文档（`docs/Windows/**` 12 份、`docs/README.md`、根 `README.md`）逐项比对；共发现 **1 处严重过期（版本号落后两个大版本）+ 10 类事实性偏差 + 2 处遗漏**，已按实测值全部修订；文档与 v1.8.0 实际代码/产物现已一致。

## 会话总结

- 本次共处理 1 个任务（封版前三方文档校验与修订）。
- 关键收获：
  1. **文档校验必须锚定「单源证据」**：版本看 `pubspec.yaml` + `git`，UI 看枚举/字段，数据看 `count()`，产物看字节数——文档互引会放大历史漂移（本次即出现 README 落后两个大版本、两个文档互称旧版本号）；
  2. **「当前状态文档改事实、历史记录只追加指针」**是可复用口径：既保证现状如实，又不抹掉取证过程；
  3. **git tag 与 `pubspec` 版本会脱钩**：release 提交只递增版本号也能发布，校验版本类陈述时须同时查 `git tag`。
- 遗留事项：补打 v1.7.0~v1.8.0 tag；如需「关闭行为/系统托盘」独立文档再评估。
