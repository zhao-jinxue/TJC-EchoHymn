## 解决思路

### 任务 3（自定义标题栏 + 用户手册按钮）—— 方案对比

- **方案 A：自绘标题栏（选定）**。原生窗口去掉 `WS_CAPTION`（保留 THICKFRAME/MINIMIZEBOX/MAXIMIZEBOX/SYSMENU），Flutter 顶栏自绘「用户手册 / 最小化 / 最大化·还原 / 关闭」按钮组。
  - 优点：用户手册按钮可**精确置于最小化按钮左侧**；样式与主题完全一致；彻底去掉系统标题栏与 Flutter 顶栏并存的冗余观感；拖到屏幕顶部吸附/Win+方向键等系统能力通过保留样式得以延续。
  - 关键实现：拖拽用 `ReleaseCapture + SendMessage(WM_NCLBUTTONDOWN, HTCAPTION)` 进入系统标题栏拖拽循环（最大化拖拽自动还原）；`SetMinClientSize` 改用实际窗口样式计算外框（无标题时不加标题高度）；最大化状态由 native `WM_SIZE` 检测 `IsZoomed` 变化推送给 Dart（`onWindowMaximizedChanged`）驱动按钮图标切换。
- **方案 B：Dwm 扩展客户区 + 保留系统按钮**。复杂且与现有客户区尺寸/居中逻辑耦合，否决。
- **方案 C：原生标题栏内嵌子窗口按钮**。子窗口被裁剪在客户区内，无法稳定渲染到非客户区，否决。

### 任务 2（播放快捷键）—— 通用方案

- 采用**通用播放器快捷键**：空格/Ctrl+P 播放暂停、Ctrl+→（兼 Alt+→）下一首、Ctrl+←（兼 Alt+←）上一首、Ctrl+↑/↓ 音量、Ctrl+M 静音、F1 手册，并支持键盘媒体键（mediaPlayPause/mediaTrackNext/mediaTrackPrevious/audioVolumeUp/audioVolumeDown/audioVolumeMute）。
- 实现位置：`app.dart` 用根 `Focus(autofocus, onKeyEvent)` 包裹 `MaterialApp`，任意焦点（含弹窗路由）的按键事件沿 Focus 链冒泡统一处理；`kNavigatorKey` 供 F1 弹窗。
- 细节：切换类动作忽略 KeyRepeat（防长按连发）；音量允许长按连续调节；**输入框聚焦时空格放行**（`_isTextInputFocused` 查 `EditableText` 祖先），避免搜索框/歌单命名误触发。
- `AudioService` 新增 `_volume/_muted`、`changeVolume/toggleMute` 与 `AudioService.instance` 静态引用（快捷键无需访问 HomeScreen 状态）。

## 任务 3：标题栏 / 顶栏布局修正（重叠问题）

### 提问

### 解决思路

- **诊断**：用 `GetWindowLong/GetClientRect/ClientToScreen/DwmGetWindowAttribute` 检查用户窗口——`WS_CAPTION` 已移除、客户区顶部偏移仅 6px（标准边框）、窗口尺寸正常，系统层面无标题栏残留；PrintWindow + 千问多模态 API 截图分析确认原有实现是「单条 40px 顶栏兼标题栏」，与用户期望的「标题栏、顶栏两条独立栏」不符，视觉上按钮/标题挤在一起即用户感知的「重叠」。
- **方案（按用户思路）**：自绘窗口标题栏 + 功能顶栏**分离为两条栏**：
  - **标题栏 30px**：左侧 logo（蓝色音符）+ 应用名「EchoHymn · 聆听赞美诗」；右侧窗口按钮组（用户手册/最小化/最大化·还原/关闭，42×30）；整条空白处拖拽窗口、双击最大化。

  - **底部状态栏 40 → 30px**；标题栏与顶栏之间加 1px 分隔线。
  - 窗口最小客户区 **850×890 不变**，四部分在其中分配（内容区 = 890 - 30 - 40 - 30）。
  - 切歌刷新：`AudioService.onCurrentChanged` 回调补充 `setState`，顶栏中央歌曲随切歌联动。

### 最终结果

- **完成结论**：标题栏与顶栏分离实现完成；千问 API 截图分析确认两条栏**完全分开、互不重叠**，标题栏含 logo/名称/四按钮，顶栏含左右箭头与中央「第 1 首《颂赞独一真神》」。
