## 任务 4：软著 Step 2 源代码格式化（txt+docx 双产物）

### 提问

用户确认《材料准备计划》无异议，python-docx 已手装，要求按"建议落地方式"执行（校验安装 + Step 2 双产物）。

### 解决思路

- 为 clean.py 增设 build 模式：读 `progress_state.json` 的 step2_file_plan → 逐文件清洗并**比对计划行数做漂移断言**（代码若与已确认计划不一致即拒绝产出）→ 质检（空行/注释残留/敏感六正则）→ 截取 → txt + docx 双产物 → 复开校验。
- 断言首跑当场抓到两个真缺陷：① `strip_dart` 把三引号多行 SQL 留成含 `\n` 的单元素，破坏"元素=物理行"不变量；② 我把版心容量算错（53.5 单位而非 97），超宽行会在 Word 里不可控软换行。修复：字符串内换行逐物理行 flush（5780→5788 行，仅 sqlite_repository 246）；引入口径为"保守 53 单位显式断行的换行流"，产物=前 1500+末 1500 **物理行**，每行必一页内呈现，60 页 × 50 行完全确定。勘误以 rev1 注记进计划（文件顺序与前后 30 页策略不变）。
- Word 版式参数：A4 / 2cm 边距（版心高 728.5pt）/ 固定行距 14.5pt（728.5÷50=14.57，EXACT 规则页页恰 50 行）/ Consolas 9pt + eastAsia 宋体 / 页眉全称+版本 / 页脚居中 PAGE 域。

### 最终结果

- **完成结论**：`output/source_code.txt` 与 `source_code.docx` 产出——3000 物理行 ≡ 60 页，前 30 页止于 hymn_display、后 30 页起于 my_playlists_panel 第 353 行，断言与结构校验全过，txt↔docx 逐段一致 True。
- **关键改动**：`clean.py`（strip 修复 + wrap_stream + build 模式）、`output/source_code.{txt,docx}`、`material_plan.md`（rev1 勘误注记）、`progress_state.json`（step2 done + 段映射 + 完成 60 页；step2_file_plan 25 项置 done）、`00_README.md` 勾选、本日志。
- **验证方式**：build 内建断言（行数漂移/空行/注释/敏感/import/段落数）；docx 结构 XML 校验（字号/EXACT 行距/页边距/页眉文本/PAGE 域）；txt 3000 行 0 空行；两文件逐段 diff 一致。
- **遇到的困难**：本机 Word 仅为注册表残留（Office 11/12/14 键存在，WINWORD.EXE 全缺，COM 80080005），无法实测页数——已如实标注"60 页为几何推导"，需在有 Word 的电脑复核并导出 PDF；python-docx 环境用户手装，pip 校验 1.2.0 通过。
