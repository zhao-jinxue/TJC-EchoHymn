## 任务 5：v1.5.0 方案 B——音量百分比与上一首重叠的结构性根治

### 提问

用户截图（ScreenShot_2026-09-01_201522_090.png）反馈：方案 A（`699d457`）解决了滑轨问题，但**音量百分比数字与上一首图标重叠**。要求先给方案；三选一时选定**方案 B**（Flex Row 结构性根治），并追问右侧人声版本 👥 是否纳入设计。

### 解决思路

- **根因**（千问视觉确认截图现象 + 代码几何核算）：旧 `_buildControls` 用 `leftMax = 半宽 − 72` 手工预算，72 假定按钮组半宽 144；实际播放键 `iconSize:42` 使 IconButton 宽 58，组宽 154、半宽 77——侵入 5 画布 px，且百分比右缘与按钮组零显式间距，大字号下吃穿 IconButton 内缩留白 → 重叠。
- **方案 B（用户选定）**：`_buildControls` 改单一镜像 Row：`[Expanded(音量), 上一首, 播放, 下一首, Expanded(👥 Align 右对齐/空配重)]`。Flex 引擎把剩余宽**等分**给左右 Expanded → 按钮组绝对居中（👥 显隐不影响）+ 音量与按钮组布局级隔离（几何上不可能重叠），废除 Stack+leftMax 预算。
- **配套调整**：滑轨下限 `150/s → 40/s`——方案 B 容器变窄（基座 850 + 最大 1.9 档 Expanded 仅 ~122 画布），旧视觉恒 ≥150 下限会 Row overflow（该场景物理至多 ~147 视觉），改小下限防溢出；默认/中/大档预算核算均 ≥150 视觉，零回归。图标/百分比、滑块/轨道反向缩放策略（方案 A 遗产）全部保留。
- **👥 宽度预算**：最大档右 Expanded 仍 ~122 画布（视觉 ~232px），👥 仅需 48，无挤压风险。

### 最终结果

- **完成结论**：方案 B 实现完成——`_buildControls` 重写为镜像 Row（~80 行结构替换），`_buildVolumeControl` 下限调整 + 文档注释更新为方案 B 描述。
- **关键改动**：`hymn_app/lib/widgets/hymn_display.dart`（`_buildControls` Stack→Row 重写、`sliderW` 下限 `150/s→40/s`、注释同步）；`hymn_app/test/v150/v150_fontsize_retest_checklist.md`（新增 R41a~R41f 复测项）；本日志。
- **验证方式**：`flutter analyze` 0 issues；`flutter test` 3 项通过；`flutter build windows --release` 成功（25.5s）。千问视觉解析原截图确认重叠形态（"50%"右半压在上一首左缘）。结构上 Expanded 隔离使重叠不可能复现；R41 清单交用户实机验收。
- **遇到的困难**：几何核算发现方案 A 遗留的"视觉恒 ≥150"下限在方案 B 容器下最大档会 overflow（124.2 > 122.7 画布），调整为 40/s 兜底并在注释中量化说明（147 vs 150 视觉差）。

## 任务 6：v1.5.0 方案 B——内置字体 EchoSans，根治最大档换肤名称逐字字重不均

### 提问

用户截图（ScreenShot_2026-09-01_193224_386.png，字号最大档）：换肤菜单名称「静谧绿·草木」的「谧绿」、「晨光蓝·经典」的「蓝」「经」等字明显更细，像没加粗。

### 解决思路

- **根因**（千问逐字分析：「蓝经谧绿雅紫墨色」等整字偏细，非 hinting 方向失真）：① 菜单名称 `w500` 是中间字重，微软雅黑家族只有 Light/Regular/Bold 实体字面，w500 依赖合成插值；② 未指定 fontFamily → 逐字 font fallback，共享码点汉字（经/绿等亦属日文常用字）可能混入其他家族；③ 最大档 ×1.9 放大到肉眼可见（上次复测仅验到 ×1.6）。
- **用户选定方案 B**（内置字体），理由：软件迁移后不依赖目标机器字体环境。三选一时放弃 E（锁雅黑家族，1 行）与 C（落实体字重），取彻底方案。
- **实现**：下载 Noto Sans SC（思源黑体，OFL 可再分发）Regular/Medium/Bold 三档 OTF → `pyftsubset` 子集化（拉丁+CJK 基本区 U+4E00-9FFF+全角+标点，各 ~10.3MB）→ `pubspec.yaml` 注册 family `EchoSans`（weight 400/500/700）→ `app.dart` 在 `textTheme.apply(fontFamily: 'EchoSans')` 挂接。
- **踩坑**：① raw.githubusercontent 被重置、jsdelivr 大文件卡 0 字节 → 探测多源后走 ghfast.top 加速代理；② `ThemeData.copyWith` 无 `fontFamily` 参数、新版 Flutter 已移除 `ThemeData.apply` → 用 `TextTheme.apply(fontFamily)`（对全部样式生效，手工 TextStyle 经 DefaultTextStyle 继承）。

### 最终结果

- **完成结论**：内置字体全局挂接完成并验证通过——w500 命中实体 Medium 字面，字体不再依赖系统环境（兼顾 Android/鸿蒙迁移目标）。
- **关键改动**：新增 `hymn_app/assets/fonts/NotoSansSC-{Regular,Medium,Bold}.ttf`（子集后共 ~30.9MB）；`hymn_app/pubspec.yaml`（fonts 注册 EchoSans）；`hymn_app/lib/app.dart`（`textTheme.apply` 加 fontFamily）；复测清单新增 R42a~R42e；`docs/UI_CONFIRMATION.md` 同步。
- **验证方式**：analyze 0 issues；test 3 项通过；build 成功；冒烟启动 8s 存活无 ERROR 日志；发布包体积影响可忽略（包内音频本为 3.3GB 级）。逐字渲染效果待用户最大档实测 R42a。
- **遇到的困难**：GitHub 直连被重置 → 写探测脚本对比 4 类镜像源，ghfast.top 0.87s 最优；子集大小 10.3MB/档（2 万字全覆盖）略大于预期，为保"任意输入不缺字"接受。
- **遗留问题**：若后续在意体积，可缩窄覆盖至通用规范汉字表两级（约省一半）；R42 待实机验收。
