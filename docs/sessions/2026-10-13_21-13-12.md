# 曲谱歌词行距减半 + 歌词/记谱双放大（v1.8.5）

- 日期：2026-10-13
- 工具链：Cline + DeepSeek API
- 涉及模块：Windows 曲谱渲染（`JianpuGridView` 版式常量）/ golden 快照 / 谱面自测工具

## 任务 1：第 20 首两行歌词之间的行距压缩一半，腾出空间放大歌词与记谱

### 提问

（用户，附第 20 首《尊主为王》曲谱实机截图，2026-10-13 21:13）
「**歌词两行之间的行距感觉太大了，应该压缩一半，这样可以留出更多的空间放大歌词和记谱**」。
前情：v1.8.4 的记谱字号（`noteFontEm = 0.50`）用户已确认「字号满意」，故本轮只调版式与字号配比。

### 解决思路

**① 先量，不猜**——建立确定性测量工具 `tools/jianpu_ink_measure.py`（快照 PNG 行带墨迹）：
把竖直连续的墨迹像素行合并成「行带」，二聚类区分**记谱带**（音符 + 记号，含小节线）与
**歌词带**（汉字墨迹），输出三个指标：**歌词行距**（相邻歌词带中心距）、**歌词净空**
（两条歌词带之间的空白）、**记谱÷歌词墨迹比**。第一版按「矮带 = 记谱」分类被实测打脸
（小节线跨音符行 + 记号行 ⇒ 记谱带反而更高），改为**「页面首带所属簇 = 记谱」**（每块必以乐谱行开头）。

**② 定位根因（量出的几何 + 字体度量复算）**：旧版式每行行高都远大于其墨迹 ——
- 音符行 1.34 × 记谱字号，而数字墨迹只占字面框 **0.345 em**（字面框 hhea ascent 0.877 em）
  ⇒ 数字上方白留 0.28 em（≈ 0.19 槽宽）；
- 歌词行 1.7 × 歌词字号，只装 1.15 em 字面框（墨迹占 0.16~1.04 em）⇒ 上下各白留 0.275 em；
- 块间距 0.55 槽宽 = 纯空白。
⇒「两行歌词的净空」≈ **1.95 槽宽**（第 20 首快照 128 px @ 槽宽 65）—— 这就是用户看到的「行距太大」。

**③ 方案对比与取舍**：
- 思路 A「只压行高、字号不动」→ 净空可压到 ~0.95 槽宽（−52 %），但歌词/记谱没变大，
  与用户同一条要求的后半句不符；
- 思路 B「只放大字号、行距不动」→ 完全没解决用户的抱怨；
- **思路 C（选定）= 行盒贴合墨迹 + 行高贴合内容 + 释放的空间按「同一光学比」放大字号**：
  净空公式 `clear = (音符行 + 下方记号行 + 歌词行 + 块间距) − 0.88 × 歌词字号`，
  歌词字号每放大 1 em 只多 0.27 槽宽成本 ⇒ **「行距变紧」与「字号变大」可以同时要**；
  并守住用户已认可的「记谱墨迹 ≈ 歌词墨迹 42 %」这个光学比（只等比放大两者）。

**④ 关键实现细节**：
- 新增 `noteBoxEm = 0.74` 收紧音符 `Text.height`（1.0 → 0.74 em）：Flutter 按 ascent 比例摆基线
  （0.877 × 0.74 = 0.649 em）⇒ **字形大小与基线位置都不变**，只砍掉数字上方的白边；
- 记号行高由**全库逐格实测上限**定（延长记号 0.30 + 单点 0.15 = **0.45 em**，块首 48 处）
  ⇒ 取 0.46/0.45 后记号不再溢出本行，块间距才敢压到 0.14 而不与上一行歌词相撞；
- 增时线/休止/附点改用 `symbolBoxEm = noteBoxEm / 0.92`，保证与数字**同一基线**
  （新行高下错位会更明显；这也是 row 高改小后暴露的连带项）。

### 最终结果

- **完成结论**：试改达成用户提出的数字 —— 两行歌词之间的**净空 −48 %（≈ 一半）**，
  同时**歌词墨迹 +12 %、音符墨迹 +15 %**，两者比例仍是用户认可的 **42 %**；列宽/同列对齐零影响。
  同时把「行距不可能整体减半」的口径写进文档（墨迹本身已占 ≈ 0.9 槽宽）。
  ⚠️ **该版式随后被用户目视裁定回退**（复原到既有行距方案）→ 见任务 2，实际留存的只有
  工具 / 快照 / 论证。
- **关键改动**：
  - `hymn_app/lib/widgets/jianpu_grid_view.dart`：新常量 `noteBoxEm`(0.74)/`symbolBoxEm`/
    `lyricLeadingEm`(1.15)；`noteFontEm` 0.50 → **0.56**、`lyricFontEm` 0.54 → **0.60**、
    `noteRowEm` 1.34 → **0.86**、`markUpEm` 0.50 → **0.46**、`markDownEm` 0.58 → **0.45**、
    `blockGapEm` 0.55 → **0.14**、`blankEm` 0.30 → **0.20**；音符/休止/增时线/附点行盒与
    「同一基线」对齐；歌词行盒与 `height` 单源化；
  - `hymn_app/test/jianpu_golden_test.dart`：新增第 20 首第 1 节 golden（1920×1080，与实机同口径）；
  - `hymn_app/test/jianpu_grid_test.dart`：新增「歌词行距/字号版式」回归用例（净空落在旧版式
    35 %~60 % + 字号/行高/块间距断言）；
  - `tools/jianpu_ink_measure.py`（新增，快照行带墨迹实测）；
  - 文档：`README.md`、`docs/Windows/{SESSION_SUMMARY, UI_CONFIRMATION §5.29, SCORE_SELFTEST, CODE_REFERENCE}.md`；
  - `hymn_app/pubspec.yaml` `1.8.4+1` → **`1.8.5+1`**。
- **验证方式**：`flutter analyze` 0 issues；`flutter test` **63 通过**（61 → 63）；6 张 golden 全部
  重生成并目视核对（第 20/1/9/163/283 首）；`tools/jianpu_ink_measure.py` 实测
  —— 净空 128 → **66 px**、行距 158 → **99 px**、歌词墨迹 30 → **33.5 px**、音符墨迹 11 → **12.6 px**。
- **遇到的困难**：① 测量脚本的分类口径先错（小节线让记谱带更高）→ 改为「首带定类」；
  ② 并行执行「重生成 golden」与「量 golden」导致量到旧文件（假象：改了常量数值不变）
  → 串行执行即可，已记入经验。
- **遗留问题**：`noteFontEm`/`lyricFontEm` 仍可单独微调（记谱再小 0.50 → 37 %；
  两者一起放大 0.60/0.64 → 净空仍 ≈ 一半）；**v1.8.5 安装包待用户确认版式后制作**
  （v1.8.4 安装包因此未出，改为随 v1.8.5 一并产出）。

## 会话总结

- 本次共处理 **2 个任务**（① 曲谱歌词行距减半 + 歌词/记谱双放大试改；② 按用户裁定复原 + 出安装包）。
- 关键收获：
  1. **版式调整必须先有测量工具**：「行距」这类描述无法直接改 —— 把「歌词行距 / 净空 /
     墨迹比」变成可复算的数字后，改动与验收都变成「改常量 → 重量 → 对比」（本次试改的
     数字正是靠它证明的）；
  2. **「行距大」未必是缺陷，可能是呼吸区**：把行高按墨迹压紧后整页数字指标都「更漂亮」，
     但观感变局促 —— 版式问题**最终以用户目视为准**，数字只用来把改动讲清楚；
  3. **复原也要有证据**：`git checkout <旧版本> -- <路径>` + golden 逐字节比对（`git diff` 为空）
     比「手工改回常量」可靠得多，且能顺手把「没改到」的地方暴露出来；
  4. **回退不等于白干**：把试改的几何论证与测量工具留在文档/工具库里，下一次讨论行距时
     直接有数据可依（这也是本次 v1.8.5 的净留存）。
- 遗留事项：`tools/verify_installer.ps1` 需管理员 PowerShell（仍未跑，沿用 2026-09-24 A/B 结论）；
  `installer/output/` 内仍留有 v1.8.1 / v1.8.2 旧产物（分发时只用 v1.8.5 双产物）。
