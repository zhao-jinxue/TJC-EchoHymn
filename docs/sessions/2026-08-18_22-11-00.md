- 日期：2026-08-18 22:11

## 提问

为 EchoHymn 增加日志功能，要求：

1. 在 `echo_hymn.exe` 同级目录创建日志目录，输出日志
2. 只保留 7 天的日志（**数量的 7 天**，即最多保留 7 份日志文件，按轮转删除，而非按时间跨度）
3. 包含程序库文件的加载日志
4. 包含 UI 的生成日志
5. 包含人机交互的日志
6. 包含个人歌单的创建、修改的详细日志
7. 包含诗歌播放的日志
8. 包含异常发生时，异常原因的日志

## 解决思路

**分析**：项目为 Flutter Windows 桌面应用，状态文件 `state.json` 位于 `echo_hymn.exe` 同级目录。日志系统需要：

1. **位置**：与 `state.json` 同级（`logs/` 目录），通过 `Platform.resolvedExecutable` 获取 exe 目录
2. **轮转**：按天轮转（`app_yyyy-MM-dd.log`），保留**最近 7 份文件**（数量规则，与日期连续性无关）
3. **写入安全**：Future 链串行写队列 + 原子写，写失败静默不影响应用运行
4. **分类标签**：`LIB`（库加载）/ `UI`（UI生成）/ `ACTION`（人机交互）/ `PLAYLIST`（歌单）/ `PLAY`（播放）/ `ERROR`（异常）/ `SYS`（生命周期）

**方案对比**：

- 引入第三方日志库（如 `logging`）：增加依赖，功能单一，仍需自己写文件轮转
- **自研 LogService**：无新依赖、完全控制格式与轮转策略、与 `AppStateService` 风格一致 → **选定**

**集成点**：

- `main.dart`：日志初始化 + 全局异常捕获（Flutter 框架层 + 平台通道）
- `app_paths.dart`：数据根目录定位日志
- `sqlite_repository.dart`：数据库打开/数据统计/歌单创建/修改/重命名/删除日志
- `chinese_convert_service.dart`：简繁映射表加载日志
- `audio_service.dart`：播放库加载 + 播放/暂停/继续/上下首/停止/异常日志
- `app.dart` / `home_screen.dart` / `hymn_display.dart`：UI 生成 + 交互日志
- 三个左栏面板 + 歌单弹窗：交互与歌单详细日志

### 乱码修复记录（用户反馈 auto-release.log 中文乱码）

**根因**：post-commit 钩子用 `>` 将 pwsh 7 输出（UTF-8 **无 BOM**）重定向到日志文件；Windows PowerShell 5.1 的 `Get-Content` 默认按 ANSI/GBK 解码 → 中文乱码。

**修复（三处）**：

1. `tools/git-hooks/post-commit`：去掉 `>` 重定向到日志 → 改为 `> /dev/null`，由脚本自写日志
2. `tools/publish_windows.ps1`：
   - 日志自写为 **UTF-8 with BOM**（5.1/7 均可正确识别中文）
   - 脚本本身添加 **UTF-8 BOM**（否则 PowerShell 5.1 按 GBK 解析无 BOM 脚本 → 语法错误/乱码）
   - 构建前临时放宽 `$ErrorActionPreference`：flutter 正常提示写 stderr，在 5.1+Stop 下被误判 `NativeCommandError` 中断
   - 打包前剔除 build 输出中的运行产物（logs/state.json/残留 data/），防止污染与 Copy-Item 容器冲突；目录先建再复制
3. 验证：用与用户相同的 `powershell` + `Get-Content`（无 `-Encoding`）读取 → 中文正常
