## 一、数据流

```text
APK(assets/NNN.csv)  →  tools/import_apk_csv.py  →  data/tjc_hymn.db
                                                    ├── jianpu_score （一首一行：行数/列数/块数/节数/对齐标记）
                                                    ├── jianpu_row   （一行一格：行类型/节号/列数/原样文本）
                                                    └── jianpu_cell  （列 = 拍点：音符/记号/小节线/歌词音节）
                                     ↓
        SqliteRepository.loadJianpuScore()  →  JianpuScore  →  JianpuGridView（EchoHymn 风格渲染）
```

**核心不变式：同一列 = 同一拍点。** 音符、记号（减时线 / 低·高音点 / 延长记号）、
小节线（`rowspan` 跨行）、歌词音节全部落在同一列 —— 对齐来自**数据**，
渲染层不做任何时间→像素换算。

### 按节显示（一页一节）

- 实现：`JianpuGridView(stanza: k)` 过滤**歌词行**；`hymn_display` 里 `_pageCount = 谱面节数`，
  复用歌词页的翻页条与 `autoPageIndexFor`（自动模式跟随播放进度切节）。
- **数据前提（务必理解）**：全库 474 首实测**没有**「一块一节」结构（每块仅 1 节歌词且节号互异 = 0 首），
  即**一段旋律承载多节歌词** → 按节过滤只改变歌词行数，**谱面内容不随节变化**。
- 节号标签 `(k)` 只在每首**第 1 个乐句块**里给出（其余块直接写音节）→ 断言/统计需按此口径。
- **逐节过滤规则（v1.8.2 定稿，修「有副歌的曲子没词」+ 用户裁定收口）**：
  1. 非歌词行（音符/记号/小节线）恒显示；
  2. **块内歌词行数 < 全曲节数** ⇒ 该块是**副歌 / 各节共用句**（印刷本只写一遍）
     → **每一节都显示**（`JianpuBlock.sharesLyricsAcrossStanzas`）；全库 **280 首**含此类块（584 块）；
  3. 歌词行**缺节号**（旧库/异常数据）⇒ 照旧显示，避免丢词；
  4. 其余按**歌词行在块内的位置**归节：**第 i 行 = 第 i 节**；
     **位置 > 节数的行 = 块内叠句 ⇒ 直接抛弃**（用户 2026-10-12 裁定：这类叠句是
     **四声部合唱的歌词**，不属于任何单独一节 —— 第 242 首「请救主进来…」即此类；
     全库 **65 行 / 25 首**，如第 18 首块 2 的「安宅要再来…」、第 51_a 首每块末尾的重复句）。
     位置比行上记的节号可靠：第 111 首首块每行都印 `(1)`，按节号过滤会丢第 2/3 节首行。
- **节数推导（`JianpuScore._deriveStanzaCount`）**：节数 = **带 `(k)` 节号的行数**
  （**只看行数、不看节号取值**；第 111 首全部印 `(1)` 仍得 3）；**完全没有节号（或只标一个）
  ⇒ 单节**（印刷本对单节诗不标节号；全库仅第 460 首《愿主赐福保佑你》是此形态，用户确认
  「源数据只有一节」）→ 不分页、歌词全部同页显示；数据库 `jianpu_score.stanza_count`
  只作兜底 —— 它按「行内位置」统计会被叠句虚增（25 首，如第 18 首 3 节记成 6）
  → 修订后页数同步修正 **22 首**（含第 460 首 2 → 1）。
- 节号 `(k)` **只在它标示的那一节显示**（第 111 首那种「每行都印 (1)」的数据不再显示错节号）。
- **修订前后全库模拟**（2026-10-12，v1.8.2 口径）：抛弃块内叠句 **65 行**；
  新增显示 **1862 行 / 282 首**（副歌/共用块 + 错标节号行）；仍在的页上被隐藏的行
  **仅 2 行**（第 111 首首块第 2/3 行 → 改在各自节显示）；无「本该显示却消失」的回归。
- **模式归属（v1.7.2 对调）**：一页一节网格挂在「**曲谱**」按钮；「**简谱**」按钮恢复为
  扫描图片（印刷四声部谱，参考图）；整页多节并列形态移除（用户不要"多声部"观感，
  网格只呈现 CSV 的主旋律**单声部** + 一页一行歌词）。

### 单声部过滤：只留「最上面那一行音符」（2026-10-13，v1.8.3）

用户反馈（第 1 首《颂赞独一真神》）：**首/末歌词行上下各多出一行简谱**。

- **源 CSV 块内布局**（用印刷本 `1_简谱.png` 交叉确认）= 四声部：
  `[上方记号] S 音符行 [下方记号] [上方记号] A 音符行 歌词行… [上方记号] T 音符行 B 音符行 [下方记号]`
  —— **S/A 在歌词上方、T/B 在下方**；第 1 首这种排版里 S 行没有自己的下方记号行。
- **旧实现缺陷**：按「遇到 `mark_down` 即第一声部组结束」判组 → S 行无下方记号 → A 行被一并画出。
- **新规则**（`JianpuScore._firstVoiceRows`）：保留 = **全部歌词行** + **块内第一个音符行**
  + 它**上方紧邻**的记号行 + 它与**下一个音符行之间含「下标记号」**的行；其余声部行/空行丢弃。
- **记号归属靠字形**（关键）：`D`（低八度点）/`B`（减时线）属**上方**声部 → 保留；
  `U`（高八度点）/`E`（延长记号）属**下方**声部 → 丢弃。
  ⚠️ **不能用 `dots` 字段判断**：高八度点字形 `MUDN` 同样含字母 `D`（`dots` 记成 1）→
  必须比对字形字母串并排除同时带 `U` 者（第 111 首 `MDN` 行 = 主旋律低音点 → 保留；
  第 9/102 首 `MUDN`/`MEN` 行 = 次声部记号 → 丢弃）。
- **影响面**（全库）：首组音符行 > 1 的块 **330 个 / 128 首**；音符行净减少 **146 行**；歌词行不受影响。
- 小节线跨行随之缩短（只跨第一声部的音符/记号行）✓ 与单声部形态一致。

### 记谱字号 = 歌词视觉大小的一半（2026-10-13，v1.8.3）

用户要求：**在保持词谱对齐的前提下**，把简谱字号与「点横」（八度点/减时线）字号
做到**只有歌词字号的一半**，并同步缩放**简谱竖线**。

- **度量事实**：记谱字体数字墨迹高 **0.3447 em**（1~7 码位 0.335~0.367）；
  楷体汉字墨迹高 **0.766 em**（快照像素实测）。
- **修订前**：记谱字号 = 1.0 × 槽宽、歌词字号 = 0.54 × 槽宽
  → 音符墨迹 **0.345** 槽宽 vs 歌词墨迹 **0.414** 槽宽 = **83 %**；
  快照实测 **音符行 15 px vs 歌词行 18 px**（用户所说「等同」）。
- **唯一可行解 + 硬约束**：列宽（拍点间距）与歌词字号都不能动（对齐 = 同列同 x；
  歌词字宽 ≈ 1 em 歌词字号必须 ≤ 1 列宽，否则相邻歌词字互挤）→ 歌词**不能放大**，
  只能**把记谱字形缩到列内**（记谱字号与槽宽解耦）→ 对齐完全不受影响。
- **系数**：`0.3447 × f = 0.5 × (0.54 × 0.766)` → **f = 0.60**
  （`JianpuGridView.noteFontEm`，含论证注释，可单点调整）。
- **同步缩放的量**：音符/休止/增时线/附点字形、变音记号、八度点直径、减时线（宽 + 厚）、
  延长记号框、**小节线宽度**；行高按 f 缩放（1.34/0.50/0.58 → 0.80/0.30/0.35 槽宽）。
  **不动**：歌词字号、歌词行高、列宽、槽宽上下限。
- **实测结果**（同一张 `jianpu_283_stanza3.png`）：音符行墨迹 **15 → 9 px**、
  歌词行 **18 → 17.5 px** → 视觉比 **83 % → 51 %** ✓。

### 按块宽渲染（2026-09-23，v1.7.1）

- 每个乐句块用**自己的列数**铺满可用宽（与 APK 每表独立排布同构；列数少的块字号更大）；
- 块内行宽差异（`163`/`197`/`297`，源数据自身问题）按**块内最大行宽**（`JianpuBlock.colCount`）处理：
  窄行右侧留空、同列仍同 x、不与其它行错位；
- 总像素高超过可用高时**整体等比收缩**（保持块间字号比例），否则纵向滚动；
- 「播放时高亮当前拍点/乐句」经用户确认**不做**（已从遗留清单移除）。
- **单声部过滤（v1.7.3）**：源 CSV 为**四部合唱谱**（每块 = S,A,词,T,B 五行组）；
  `JianpuScore.build(firstVoiceOnly: true)` 每块只保留第一个「记号上+音符+记号下」声部组
  - 全部歌词行（「曲谱」模式使用）；小节线跨行 = 块内连续乐谱行数（过滤后 3 / 全声部 6，
  与源 `rowspan` 等价）。全声部形态 = `firstVoiceOnly: false`（组件快照/自测）。
- **垂直居中（v1.7.4）**：曲谱页内容不足一屏时**整块垂直居中**（与歌词页同口径：
  `ConstrainedBox(minHeight: 视口净高)` + `MainAxisAlignment.center`）；超一屏从顶滚动、不裁顶。

> ⚠️ **字体码位坑**（2026-09-22 实测）：印刷记谱字体 `EchoJianpu` 的数字字形挂在
> **CJK 码位**（`0x4e52` = `1` … `0x4e5d` = `7`；`0x5d4c` = `0`；`0x5d1f` = 增时线；
> `0x5d3d` = 附点），**不是** U+0031 等 ASCII 码位。
> 视图必须按码位取字形（`String.fromCharCode(...)`），否则整行数字静默不可见
> （golden 快照正是为捕捉此类"编译通过但看不见"的问题而设）。

## 四、变更谱面数据时

1. 改 `tools/import_apk_csv.py`（解析规则 / 表结构）后 **必须重跑 L0 + L1**；
2. 表结构变更后同步改 `SqliteRepository.loadJianpuScore()` 与 `lib/models/jianpu_grid.dart`；
3. 新增记号语义时，同时补 `JianpuGridView` 绘制分支与 `test/jianpu_grid_test.dart` 断言；
4. 数据侧统计口径变化（行数/格数/列宽）→ 更新本文档「当前基线」表。
