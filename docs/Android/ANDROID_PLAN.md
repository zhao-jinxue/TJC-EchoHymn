# EchoHymn Android 版开发计划（2026-10-11 重订 · 手机 / 平板双分支，手机优先）

> **文档定位**：Android 平台**路线图与阶段任务的唯一准绳**（历史与进度口径见同目录 [SESSION_SUMMARY.md](SESSION_SUMMARY.md)；2026-09-11 立项初版全文归档于 [ANDROID_PLAN_2026-09-11_初版.md](ANDROID_PLAN_2026-09-11_初版.md)）。
> **本次重订（2026-10-11）**：原版只有「环境 → 最小可跑 → 数据链路 → UI 移动化」四阶段；
> 现按新需求重订为 **双分支（手机 / 平板）+ 手机优先**，并把 **UI 设计 / 功能实现 / 代码管理 / 模拟测试 / 软件发布** 五大环节写成可执行清单。
> **三大参照基线**：① 第三方参照物 `com.tinanlin.tjc_hymn_cn_v2.4.2.apk`（逆向机制见 `docs/knowledge/TJC_APK_JIANPU_RENDER.md`）；
> ② Windows 定稿（`docs/Windows/UI_CONFIRMATION.md` v1.8.0 + `UI_DESIGN_TEMPLATE.md`）；③ 现有 Flutter 代码资产（`hymn_app/lib/`，v1.8.0，474 首）。
> **当前基线**：Windows **v1.8.0**（`hymn_app/pubspec.yaml` = `1.8.0+1`）；Android 侧阶段 0 环境已完成，`hymn_app/android/` 仍是 `flutter create` 默认工程（**零适配**）。

## 〇、重订说明：为什么是「双分支」

| 决策 | 内容 | 理由 |
| --- | --- | --- |
| **产品形态一分二** | **Android 手机版**（竖屏单手，先做）与 **Android 平板版**（横屏大屏，后做） | 信息密度差 2~3 倍：手机要「一屏一件事」（歌词/谱面为主体、侧栏抽屉化），平板可保留 Windows 的「多栏并列」思路 → 强行一套布局会两头不讨好 |
| **手机优先** | 平板分支在手机版**验收通过后**再从手机分支切出 | 手机版覆盖全部**功能**与**数据链路**（平板只差布局）；先验证高风险项（音量/后台播放/素材分发/DB 落点），避免两条分支同时踩同一批坑 |
| **共核差异外壳** | 业务核心（`models/` `services/` `data/`）两分支**完全共用**；差异集中在 UI 层 | 防止长期分叉：修一个 bug 要改两遍 |
| **分支命名** | `main`（Windows 主线，**只读不破**）· `android/phone`（手机）· `android/tablet`（平板） | 见 §五「代码管理」 |
| **每分支再分四变体** | 每个平台分支再分 **全量音频版 / 钢琴版 / 人声版 / 无音频版** → 手机 4 + 平板 4 = **8 个发布变体**（体积：3.00 / 1.72 / 1.48 / 0.58 GB） | 同一套代码**用构建变体（Gradle flavor + `--dart-define=AUDIO_VARIANT`）区分**，**不为此再开 Git 分支**（差异是「功能开关 + 素材打包 + 裁剪 DB」而非布局）；详见 §1.4 ⑤ |

## 一、目标、范围与验收总纲

### 1.1 目标平台与系统基线（以最新 Android 为目标）

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 目标系统 | **Android 16（API 36）** 为编译/目标基线；**Android 8.0（API 26）** 为最低支持 | API 36 = 当前最新；环境已装 `platforms;android-36` |
| `compileSdk` | **36** | 环境已装（Flutter 3.44 亦要求 ≥36） |
| `targetSdk` | **36** | 跟随最新；须正面适配下方五项「新系统硬要求」 |
| `minSdk` | **26**（落地时最终确认） | 更低需额外兼容分支且收益极低；素材/解码链路无 26 以下诉求 |
| ABI | `arm64-v8a` + `armeabi-v7a` + `x86_64`（模拟器） | 注意 **16 KB page size** 要求（见下） |

**新系统硬要求清单（targetSdk 35/36 必须正面处理，不能靠默认行为）**

| # | 要求 | 对 EchoHymn 的影响 | 落地要点 |
| --- | --- | --- | --- |
| 1 | **强制 edge-to-edge**（API 35+，无法 opt-out） | 标题栏/状态栏/播放条会与系统栏重叠 | 全屏 `SafeArea` + `SystemUiOverlayStyle`（透明栏 + 亮/暗图标随 `AppPalette.brightness` 切换）；**弃用桌面自绘 30px 标题栏**（§3.1） |
| 2 | **预测性返回（Predictive Back）** | 返回手势会先「预览」上一界面 | Manifest 加 `android:enableOnBackInvokedCallback="true"`；可返回点改 `PopScope(canPop:, onPopInvokedWithResult:)` |
| 3 | **前台服务类型**（API 34+ 强制声明原因） | 后台播放必须 `foregroundServiceType="mediaPlayback"` | 需 `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MEDIA_PLAYBACK` 权限；配媒体通知（§4.5） |
| 4 | **通知权限运行时申请**（API 33+） | 媒体通知不申请则不显示 | `POST_NOTIFICATIONS` 首次播放前弹一次；拒绝后给设置页入口（降级为仅前台播放） |
| 5 | **16 KB memory page size**（Play 2025-11 起新应用/更新强制） | `sqlite3_flutter_libs` 等含原生库依赖必须 16KB 对齐 | 升 NDK ≥ 27；`flutter build apk --analyze-size` + 16KB 校验纳入发布前基线 |

> `READ_MEDIA_AUDIO`（API 33+）仅当读取**外置**音频时申请；素材全在应用私有目录（推荐，见 §7.5）时**无需任何存储权限**。

**自动翻页与进度来源（代码事实）**

| 环节 | 实现 | 位置 |
| --- | --- | --- |
| 进度来源 | `AudioPlayer.onPositionChanged` → `_positionCtrl` | `lib/services/audio_service.dart`（L30 / L70~75） |
| 对外接口 | `positionStream` / `durationStream` / `currentHymn` | 同上 |
| 消费点 | 订阅为 `_pos` → `_applyAutoPage()` 重算页码 | `lib/widgets/hymn_display.dart` L194~205 |
| 换算函数 | `autoPageIndexFor({position, totalSeconds, pageCount})`（**等分推算**） | `lib/models/hymn.dart`（契约见 `CODE_REFERENCE.md`） |
| 总时长来源 | **优先取 DB 预存**：`hymn.durationOf(version)` ?? `audioDurations.values.first` | `hymn_display.dart` L186~190（`tjc_hymn.audio_durations`） |

- `audioplayers` 是跨平台插件（Windows 走 Media Foundation、Android 走 ExoPlayer/MediaPlayer）⇒ **有音频变体的自动翻页在 Android 与 Windows 表现一致，零改动可用**。
- **无音频版没有进度流**（不播放音频）⇒ 自动翻页采用**「虚拟进度」**方案：内部时钟按 DB `audio_durations` 的总时长推进，**复用同一个 `autoPageIndexFor`**；零新增数据、翻页节奏与有音频版一致；界面**不出现任何播放控件**，仅由翻页条的「手动 / 定时」开关控制。

#### 3.1.13 手势决策：**不注册边缘手势，全部图标点击**

| 决策 | 内容 |
| --- | --- |
| **不使用边缘滑动手势** | 打开抽屉只用 `≡` / `⋮`；关闭用 `✕`、点遮罩、或**系统返回手势**。**取消**原设想的"边缘右滑开抽屉 / 边缘左滑开源考" |
| **冲突原因** | Android 10+ 全面屏手势的「返回」由**屏幕左/右边缘起划**（系统保留带约 20~40dp）触发。App 若同时注册边缘滑动，会出现"划一次既开抽屉又触发返回"的双响应；Android 15+ 预测性返回还会出现手势预览与 App 动效打架 |
| **能否排除系统手势区？** | `View.setSystemGestureExclusionRects` 属**原生 View API**，Flutter 无公开稳定接口；且排除区会削弱系统返回手势（Play 审核亦不鼓励滥用）→ **不采用** |
| **仍保留的手势（主体区白名单）** | ① 单指纵向滚动；② 谱面/扫描图：单指平移 + **双指捏合缩放** + 双击复位；③ 长按 = 上下文菜单。这些起手于**屏幕中部**，与边缘返回手势无空间重叠 |
| **明确禁止的手势** | 边缘起划、左右滑动切歌、抽屉边缘拖拽关闭（下拉关闭也不做） |
| **切歌入口** | 播放条 `⏮/⏭` + 通知栏媒体按钮 + 耳机线控（阶段 D）——**无手势入口** |
| **系统返回的落点** | 抽屉开 → 关抽屉；搜索/设置/手册/歌单/沉浸态 → 回上一级；主界面 → 让系统处理（回桌面） |
| **兜底可达性** | 每个手势动作都有**等价图标按钮**（缩放 `＋/－`、复位 `⟲`、翻页 `◀/▶`）→ 纯图标即可完成全部操作，同时满足无障碍（TalkBack）要求 |

> **一句话定稿**：手机版**一切功能都可由图标/按钮完成**；手势只作为"中间区域的顺路优化"（滚动、捏合、长按），**不与系统边缘手势争夺同一片区域**。

**系统导航方式的判定（三层：准 → 简单 → 兜底）**

| 层 | 手段 | 判据 |
| --- | --- | --- |
| 1（首选·最准） | 原生 `Settings.Secure.getInt(cr, "navigation_mode")` + `WindowInsetsCompat`（`systemGestures` / `mandatorySystemGestures` / `tappableElement`）→ MethodChannel 暴露 `navigationMode` | `0` = 三键 / `1` = 二键 / `2` = 手势（走 §4.2 的原生桥，与媒体集成同一处） |
| 2（纯 Flutter 即可） | `MediaQuery.systemGestureInsets` + `MediaQuery.viewPadding.bottom` | 手势导航：左右 `systemGestureInsets` > 0、`viewPadding.bottom` 较小（≈16~24dp）；三键导航：`systemGestureInsets` ≈ 0、`viewPadding.bottom` ≈ 48dp |
| 3（用户兜底） | 设置页「显示 → 底部导航条」：**自动（默认，跟随系统）/ 总是显示 / 总是隐藏** | OEM 判定不准 / 分屏 / 折叠屏切换时人工可改 |

> 设计逻辑：**不问"能否排除系统手势"（Flutter 无该接口，见 §3.1.13），只问"这条空间要不要用"**——系统有导航栏 → 顺势放我们的导航条（视觉上连成一体）；系统没有 → 一条都不占，全给主体区。

**态 ③（默认形态）：系统导航栏可隐藏 → 我们的条「总是隐藏」**

| 项 | 定稿 |
| --- | --- |
| 我们的「翻页 + 浏览导航条」 | **默认「总是隐藏」**（设置项默认值）→ 一条都不占，主体区吃满（竖屏 **+56dp** / 横屏 **+48dp**） |
| 系统导航栏 | **默认隐藏**（沉浸粘性，见 §3.1.16） |
| 导航入口 | ① 主体区右下**半透明悬浮控件**（◀▶ 节 / ⏮⏭ 首，点屏唤出、2s 淡出，不占布局）；② 顶栏 `⋮` 菜单内同样四项 |
| 与态①②的关系 | 态①②降级为**兜底**：当系统/OEM 不支持隐藏、或用户在设置里选「显示系统导航栏」时，按检测结果回到"有导航键 → 显示条 / 手势导航 → 自动隐藏" |

#### 3.1.16 系统导航栏隐藏（沉浸式）方案

**结论：可以隐藏**（Flutter 内置 API 即可），故按你的要求把「底部导航条」定为**默认总是隐藏**。

| 项 | 定稿 |
| --- | --- |
| 手段 | `SystemChrome.setEnabledSystemUIMode(SystemUiMode.immersiveSticky)` —— **沉浸粘性**：从边缘/底部滑入时系统栏临时出现，随后自动隐藏（比 `immersive` 更易恢复，推荐） |
| 默认值 | 主界面 = **隐藏系统导航栏**；「底部导航条」= **总是隐藏** |
| 导航入口 | 半透明悬浮控件（点屏唤出 / 2s 淡出）+ 顶栏 `⋮` 菜单四项（上/下一节、上/下一首） |
| 设置项（兜底） | 「显示 → 系统导航栏：**隐藏（默认）** / 显示」·「显示 → 底部导航条：自动 / 总是显示 / **总是隐藏（默认）**」 |
| 兼容性 | Android 11+ **手势导航**下隐藏系统栏后**边缘返回手势仍可用**（系统保证）；**三键导航**隐藏后需**上滑唤出**系统栏；分屏 / 悬浮窗下可能不受控 → 检测或设置失败时回落到 §3.1.15 态①② |
| 与谱面沉浸态的区别 | 主界面 = 隐藏系统栏但保留"临时唤出"（`immersiveSticky`）；谱面沉浸态（§3.1.12）= 全屏 + 半透明悬浮工具栏 + 一键退出 |
| 风险（写进走查） | ① 完全隐藏系统栏会削弱"返回 / 回桌面"的可发现性（对老年用户尤甚）→ 顶栏/手册提供"如何返回"说明，并保留一键恢复开关；② 部分 OEM（MIUI / EMUI / OneUI 等）对沉浸模式有限制；③ 与 Android 15+ 强制 edge-to-edge 叠加时仍需正确处理 insets；④ **必须提供"显示系统导航栏"开关**，避免用户"退不出去" |

### 3.3 主题与字号（沿用 Windows 规范，改应用方式）

| 项 | Windows 做法 | 手机做法 |
| --- | --- | --- |
| 五套换肤 | 标题栏调色盘按钮 + 菜单 | 顶栏 `⋮` → 设置页；`AppPalette` 与 `AppColors` **零改动复用**；**另加「跟随系统深色」**选项（默认关） |
| 深色（暗夜墨） | 手动切换 + DWM 标题栏同步 | 手动切换 + 系统栏图标亮暗随 `palette.brightness`（`SystemUiOverlayStyle`） |
| 四级字号（**移动版重建，不照搬 Windows**） | `FontSizeLevel` = 默认 **1.0** / 中号 **1.3** / 大号 **1.6** / 最大 **1.9**（`lib/theme/app_fonts.dart`），实现为整棵 Navigator `Transform.scale` 等比缩放（基座 850×890） | **档位重定为 标准 1.00 / 大 1.10 / 特大 1.20 / 最大 1.30**；实现改为**只缩放文本**（`MediaQuery.textScaler`）+ 少数行高联动，**控件几何不变**（触控目标恒 ≥48dp，不随字号变化，避免破坏 edge-to-edge 与滚动）；详见下方"移动版字号基准表" |
| 系统字体缩放 | 桌面不适用 | 尊重系统 `textScaleFactor`，最终 `textScaler = clamp(档位系数 × 系统系数, 1.0, 1.40)`（防极端组合把布局挤爆） |
| 字体 | 内嵌 `EchoSans` / `EchoKai` / `EchoJianpu` | 完全一致（资产随包，不依赖系统字体） |

**为什么不能照搬 Windows 的 1.0/1.3/1.6/1.9（移动版字号设计依据）**

| 维度 | Windows | 手机 | 结论 |
| --- | --- | --- | --- |
| 显示面积 | 基座 **850×890**（≈ 0.76 M px） | 典型 **412×915**（≈ 0.38 M px，**约 Windows 的 1/2**） | 同一系数在手机上占屏比例翻倍 |
| 缩放方式 | 整树等比缩放（窗口尺寸固定，控件一起变大） | 不能缩放控件（会吃掉一屏高度、放大热区） | 只能文本缩放 |
| 极端档效果 | 最大 1.9 → 正文 20→38px，窗口仍能容纳整节 | 最大 1.9 → 正文 18→34sp，**一屏歌词只剩 3~4 行**，且顶栏/播放条被挤压 | 上限压到 **1.30** |
| 档位间距 | 1.0 / 1.3 / 1.6 / 1.9（步长 0.3） | 1.00 / 1.10 / 1.20 / 1.30（步长 0.10） | 步长减到 1/3，避免"一跳一整屏" |
| 自适应兜底 | 歌词页铺满算法（无固定字号表） | **固定基准字号表**（下方）+ 铺满算法仅在 ±25% 内微调 | 保证任何机型/字号下都可读 |

**移动版字号基准表（标准档 1.00 · 竖屏 412dp 宽为基准机型）**

| 用途 | 基准 | 说明 |
| --- | --- | --- |
| 歌词正文 | **18sp** | 由歌词页铺满算法在 18×(0.90~1.25) 内自适应；再乘档位系数 |
| 歌词标题（节号 / 副歌） | 16sp | — |
| 顶栏应用名 | 16sp | 副行歌名 13sp |
| 列表项主文本（诗歌名） | 16sp | 编号列 14sp；歌单成员 15sp |
| 源考正文 | 16sp | 行高 1.6 |
| 按钮 / chip 文字 | 16sp / 14sp | chip 高度 32dp 固定（不随字号变） |
| 播放条时间 / 状态 | 12sp | — |
| 辅助说明 / 计数 | 12sp | 三级色 |

> **大字号的排版后果与对策（写进验收）**：标准→最大档时，歌词一屏可见行数由约 **9~10 行降到 6~7 行**（412dp×915dp 机型实测口径），故 **1.30 档必须配合页内滚动**（歌词页保留 `minHeight` + 可滚动），并保证顶栏歌名、播放条时间**不截断、（模式栏）不换行**——此三条为 M3 走查必测项。

### 3.4 四种显示模式的移动化

| 模式 | Windows 定稿 | 手机实现 | 风险 / 对策 |
| --- | --- | --- | --- |
| **歌词** | 一页 = 一节 + 副歌；整块垂直居中；字号按内容铺满；底部「第 k / N 节」+ 手动/自动 | 同语义；**一页 = 一节**（竖屏更矮，容许页内滚动）；翻页条常驻底部（播放条上方）；自动模式跟随播放进度 | 窄屏长句折行 → 保留 `minHeight` + 页内滚动 |
| **曲谱**（CSV 网格） | 一页 = 一节单声部网格；槽宽 = 可用宽 ÷ 全曲最大列数；同列同 x；块宽渲染；垂直居中 | **完全复用 `JianpuGridView`**；窄屏下因槽宽被压缩 → 提供「**横屏放大视图**」按钮（临时 `landscape`）与双指缩放 | 行数多 → 纵向滚动；列密集 → 允许横向滚动（`InteractiveViewer` 包裹或手势换行） |
| **简谱**（扫描图） | `_ScoreImageView` 宽度驱动缩放；`Ctrl+滚轮` 缩放 | 改 **`PhotoView` 语义**：双指缩放 + 双击复位 + 单指平移（自绘手势，不引入新依赖）；大图**内存缓存**（`FileImage` + `cacheWidth` 防 OOM） | 上千 px 大图 OOM → 按屏宽解码 |
| **五线谱**（扫描图） | 同简谱 | 同简谱 | 同上 |
| 回退 | 无网格数据 → 回退简谱扫描图 | 一致 | — |

> **APK 参照点的正确位置**：TJC APK 的「简谱页 = WebView + CSV 拼 HTML 表格」**不采纳**；采纳的是它**「列 = 拍点、对齐在数据里完成」**的模型 —— 该模型在 Windows 侧已落成 `jianpu_*` 三表 + 自绘网格，手机侧等于**零成本继承**。

## 五、代码管理

### 5.1 分支策略

```text
main                      ← Windows 主线（v1.8.0 已发布），Android 分支自其切出；合并回 main 需 Windows 侧零退化
├── android/phone         ← 📱 手机版（当前主线，先做）       ← 本次目标
│     └── android/tablet  ← 平板版（手机版验收点后再切）
└── （Windows 修 bug）     ← 如需在 main 修 Windows bug，用 fix/win-* 分支，再 rebase 到 android/phone
```

| 规则 | 内容 |
| --- | --- |
| **切出点** | `android/phone` 自 `main` 的 v1.8.0 提交（`e8b893a`）切出；`android/tablet` 自 `android/phone` 的**手机版验收 tag** 切出 |
| **合并方向** | `android/*` → `main` **只允许「Windows 零退化」的提交**（共用代码修复）；布局壳类提交**不回 main** |
| **共享修复** | 数据/服务层 bug 在 `android/phone` 修好后 **cherry-pick 回 `main`**；避免 main 落后 |
| **提交粒度** | 一个任务（A1/A2/…）一个提交；提交信息带阶段号，如 `feat(android-A2): WindowControls 抽象与移动 stub` |
| **禁止** | 不在 `main` 上直接做 Android 布局改动；不用长生命周期的 `dev` 分支（两分支已是并行最小集） |
| **变体不进分支** | 音频变体（**full / piano / vocal / lite**）**不新建 Git 分支**：用 Gradle flavor（`applicationIdSuffix`）+ `--dart-define=AUDIO_VARIANT` 区分 → 仍是 2 个分支（phone / tablet）、每分支 3~4 个构建产物；差异只在「外壳条件渲染 + 打包白名单 + 裁剪 DB」 |
| **变体差异的写法** | 允许 `if (kAudioVariant == AudioVariant.lite)` 仅出现在**外壳 UI**（播放条/版本行/设置分组）与**打包脚本**；服务层（`AudioService` 等）用抽象 + stub（同 `WindowControls` 范式），**禁止**在业务逻辑里散落变体判断（风险 R12） |

### 5.2 目录与平台化改造原则

| 原则 | 做法 |
| --- | --- |
| **共核** | `lib/{models,services,data,theme}/` **两平台零分叉**（若必须分叉 → 抽象 + 条件导入，不写 `if (Platform.isAndroid)` 散点） |
| **外壳分层** | `lib/screens/desktop/`（现 `home_screen.dart` 归档）+ `lib/screens/mobile/`（新）+ 共享 `lib/widgets/`；`main.dart` 只做「按平台/宽度选壳」 |
| **断点判定** | 用**宽度**（`MediaQuery.size.width < 600`）而非设备型号；平台判定只用 `AppPaths.isMobile` 一处 |
| **条件导入范式** | 沿用项目既有手法（`chinese_convert_service.dart` + `_stub.dart` + `_native.dart` 三件套），`WindowControls` 照此办理 |
| **桌面不退化清单** | 每次改共用文件后必跑：`flutter analyze` + `flutter test` + Windows 实机一次（关键路径：播放/切模式/换肤/搜索） |

### 7.1 签名与 keystore（阶段 F 前置）

| 项 | 定稿 |
| --- | --- |
| keystore 生成 | `keytool -genkeypair -v -keystore echohymn-release.jks -alias echohymn -keyalg RSA -keysize 4096 -validity 10950` |
| 存放 | **仓库外**（如 `D:\Android\keystore\`）+ 备份；**绝不入库** |
| 配置 | `android/key.properties`（`storeFile` / `storePassword` / `keyAlias` / `keyPassword`）→ `key.properties` 入 `.gitignore`，`build.gradle.kts` 读它做 `signingConfigs.release` |

| 风险 | keystore 丢失 = 无法升级已发布应用 → 至少两处离线备份（对齐 Windows 发布规范里「产物留档」的谨慎度） |

### 7.5 素材（3.38GB）分发方案（关键决策点）

| 方案 | 做法 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- | --- |
| **A. 样本内置 + 外部导入** | APK 内只带 10~20 首样本；其余由用户用「系统文件选择器（SAF）」指定素材目录（或从电脑拷入） | 包体小（≈100MB 内）；**无存储权限也可用**（SAF） | 首次配置有步骤（需引导页 + 手册说明） | ✅ **内测首选**（阶段 B 起步即此方案） |

## 九、「跑的是 Android 而非 Windows」判定范式（沿用阶段 0 口径）

- **构建目标**：`flutter devices` 列出 `emulator-5554 / echohymn_phone36`（`mobile · android-x64`），`flutter run -d <id>` 产物为 `.apk`
- **运行时**：画面出现在 Android 虚拟手机系统内（状态栏 / 返回手势 / 通知栏均为 Android），与 `echo_hymn.exe` 窗口无关
- **代码层**：`AppPaths.isMobile == true`（mobile 分支生效）；`echo_hymn/window` 通道经条件导入**不参与 Android 编译**
