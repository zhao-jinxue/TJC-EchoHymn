# 04 人工操作指南：软著材料终审与排版 (Manual Operations Guide)

## 文档定位

AI（Cline）负责“内容提纯”（去注释、去空行、生成文本框架），而中国版权保护中心（CPCC）的审查标准是基于 **A4纸物理打印效果** 的。因此，本指南规定了 AI 无法替代、必须由人工在本地软件中完成的排版与终审操作。

---

## 任务一：源代码文档化排版（Word 操作）

AI 输出的 `source_code.txt` 是纯净代码流，您需要将其转换为符合官方规范的 PDF。

### 1. 基础页面设置

- 打开 Microsoft Word，新建空白文档。
- **纸张大小**：设置为 A4。
- **页边距**：建议设置为 上下左右各 2.0cm - 2.5cm（必须为页眉留出足够空间）。

### 2. 手动添加页眉（核心必做）

根据 CPCC 规范，每页顶部必须有页眉。

- **操作步骤**：双击 Word 页面顶部进入“页眉和页脚”编辑模式。
- **左侧输入**：您的 **软件全称 + 版本号**（例如：`智能数据分析管理系统 V1.0`）。
  - ⚠️ **绝对红线**：此处名称必须与申请表、说明书中的名称**一字不差**，不能写简称，不能漏掉空格或版本号。
- **右侧输入**：插入自动页码（格式建议为 `第 X 页 共 Y 页` 或直接数字）。
- 完成后退出页眉编辑模式。

### 3. 粘贴代码与字体设置

- 将 Cline 生成的 `source_code.txt` 内容全选复制，粘贴到 Word 正文中（建议选择“只保留文本”粘贴）。
- **字体选择**：必须使用等宽字体，推荐 `Consolas`、`Courier New` 或 `黑体`。
- **字号与行距调整（关键）**：
  - 初始尝试：字号设为 **小五号（9磅）**，段落行距设为 **固定值 13磅**，段前段后间距设为 0。
  - **目标校验**：滚动查看每一页，确保 **每一页刚好容纳 50 行代码**（最后一页除外）。
  - 如果一页超过50行，稍微调大字号或行距；如果不足50行，稍微调小。

### 4. 分页微调（防截断）

- 检查每一页的最后一行和下一页的第一行。
- **禁止出现**：一个完整的函数、类定义或循环语句被硬生生从中间切断分在两页。
- **处理方法**：若发生截断，在上一页末尾手动按回车键（Enter），将该代码块整体推到下一页，并确保调整后每页仍维持 50 行（可通过微调行距实现）。

### 5. 篇幅确认

- 总代码量 ≥ 3000 行：严格控制在正好 60 页（前30页+后30页）。
- 总代码量 < 3000 行：全部提交，有多少页算多少页，页码总数随之改变（如共 18 页）。

> **rev（2026-09-06，Step 2 实测后注记——任务一的自动化与口径修正）**
> ① 官方申报口径为"**每页 50 行以上**"，本项目材料取"**恰 50 行/页**"（更严、自洽，属主流做法）；
> ② 第 4 节"禁止函数截断"**不是官方硬性项**，且与官方另一条硬规数学上不相容——"前 30 页须从程序第 1 行连续开始"，第 30/31 页交界固定在第 1500 行，无法挑选恰逢 `}` 的行。该项降级为**美观参考，不作强制**（Cline 材料已连续截取，天然存在跨页代码行，官方不因此补正）；

## 任务二：用户操作手册完善（Word 操作）

AI 生成的 `user_manual_draft.md` 是骨架，需要人工填充血肉。

### 1. 格式转换

- 将 Markdown 文件转换为 Word 文档（可通过 Typora、Pandoc 导出，或直接复制粘贴后重新应用标题样式）。
- 添加封面页：居中写明 软件全称、版本号、申请人姓名、日期。
- 自动生成目录。

### 2. 截图替换（最易导致补正的环节）

- 找到文档中所有的 `[此处插入：XXX界面截图]` 占位符。
- **截取真实图片**：运行您的软件，截取对应功能的真实界面。
- ⚠️ **一致性核查**：
  - 截图窗口标题栏上的软件名称，必须与申请的“软件全称”一致。如果不一致，需用图片编辑工具修改标题栏文字，或隐藏标题栏截图。
  - 截图中的版本号（若有显示）必须一致。
  - 绝不能使用其他软件的截图或网图。
- 将截图插入占位符位置，图片需清晰可辨，宽度建议统一适应页面宽度。

### 3. 语境与风格复核

- AI 可能生成了过于营销化或不存在的功能描述。
- 通读全文，删除“全球领先”、“首创”等主观词汇，保持客观第三人称描述（如“点击该按钮，系统弹出对话框”）。
- 删除手册中提到但实际代码中未实现的功能。

## 任务三：跨材料全局一致性终审（交叉比对）

在导出最终 PDF 前，进行最后一次“三位一体”核对：

| 核对项 | 申请表填报信息 | 源代码文档（页眉/注释） | 用户手册（封面/截图） |
| :--- | :--- | :--- | :--- |
| **软件全称** | 智能数据分析管理系统 | 智能数据分析管理系统 | 智能数据分析管理系统 |
| **版本号** | V1.0 | V1.0 | V1.0 |
| **开发语言** | Python, JavaScript | 代码特征需吻合 | 运行环境描述需吻合 |
| **核心功能** | 数据导入、图表分析 | 包含相关函数/类 | 包含相关操作章节 |

*注：任何一项出现错别字、大小写不一致（如 v1.0 与 V1.0）、中英文标点混用，都极大概率触发补正。*

## 任务四：脱敏与安全最后检查

虽然 Cline 提示词中已要求脱敏，但人工必须二次确认：

- [ ] 源代码中无真实的数据库密码、服务器 IP、微信/AppID 密钥。
- [ ] 源代码中无开发者个人手机号、私人邮箱。
- [ ] 源代码中无第三方受版权保护的完整代码段（避免侵权风险）。
- [ ] 用户手册截图中无真实用户的隐私数据（如真实姓名、身份证号），请使用“测试用户01”等假数据。

---

## 任务五：最终输出与归档

### 1. 导出 PDF

- 将排版好的源代码 Word 和用户手册 Word，分别“另存为”或“导出”为 PDF。
- **不要**直接上传 Word 文件，防止在不同电脑上打开时排版错乱导致行数变化。
- 检查导出的 PDF 是否缺少字体、图片是否模糊。

### 2. 本地证据归档（防抄袭必备）

结合您之前提到的 GitHub 开源情况，请在本地建立独立文件夹永久保存以下材料：

- Cline 处理前的原始代码压缩包。
- Cline 生成的中间文件（`progress_state.json` 等）。
- 最终提交的 PDF 副本。
- Git 提交历史导出记录。
*作用：若未来 GitHub 上的代码被恶意抢注或商用侵权，这些材料与软著证书结合，构成完整的原创证据链。*
